# 작업 보고서 — Blender 150 × 300m 전진형 숲 맵

승인한 세로형 시안을 Blender로 제작하고, 기존 충돌·내비게이션을 유지해 새 맵과 300 × 600셀 마스크를 연결했습니다.

## 확인 위치

http://localhost:5179/forest-map-tool.html

- 정화 후와 캐릭터 시점이 기본입니다. 전체 보기로 150 × 300m 전체를 확인합니다.
- 정화 전후 전환, 마스크 표시, 미니맵 클릭 이동, WASD/방향키, 몬스터 12마리 생성과 추적을 제공합니다.
- 기존 150 × 150m 맵의 v1 모델·Blender 원본은 유지하고, 새 맵은 v2로 저장했습니다.

## 이번 구성

- 전체 150 × 300m. 남쪽에서 북쪽으로 진행하는 하나의 연속된 평지입니다.
- 평지 면적 9,914.25㎡. 주 진행 구간 폭 24~50.5m로 측정했습니다. 시작/끝 차폐 부분은 측정에서 제외합니다.
- 각 높이의 좌우 경계를 따로 정의하고 작은 요철을 넣었습니다. 원형 방이나 순환 길을 배치하지 않았습니다.
- 네 구간에서 평지 폭과 좌우 열림을 달리하고, 숲 경계에 바위 군락 7곳과 통나무 3곳을 넣었습니다.
- 이동 바닥은 높이 0m로 평평합니다. 바위·통나무는 마스크의 숲 쪽에 배치했습니다.
- 정화 전후가 같은 마스크와 배치를 공유합니다.

## 파일

프로젝트 루트 `C:\xoox`

- `art-source/forest150/v2/forest_purified.blend`, `forest_polluted.blend`: Blender 원본. 기본 저장 카메라는 전체 구도입니다.
- `data/maps/forest150/releases/v2/`: 정화 전후 GLB, 마스크 PNG, navigation.json, stats.json, validation.json, Blender 렌더.
- `data/maps/forest150/manifest.json`: 기존 URL을 유지하고 revision을 `forest150x300-v2`로 변경했습니다. 크기는 widthMeters=150, lengthMeters=300입니다.
- `scripts/forest150/build_forest.py`: 재생성 스크립트. `-- 출력폴더 render`로 모델·마스크와 렌더를 생성합니다. Blender 5.2에서 실행합니다.
- `scripts/forest150/validate-v2.cjs`: 새 300 × 600셀 검증. `node scripts/forest150/validate-v2.cjs data/maps/forest150/releases/v2`로 실행합니다.
- `src/tools/forestMap/main.ts`, `forest-map-tool.html`: 직사각형 미니맵과 클릭 좌표, 새 전체 카메라, 기본 플레이 시점.
- `src/tools/toolsCatalog.ts`, `unit-lab-tool.html`, `sector-editor.html`: 새 크기로 링크 이름 갱신.

## 내비게이션 유지

`src/maps/forest150/ForestNavigation.ts`의 충돌·A*·안전 스폰 로직은 수정하지 않았습니다. 새로운 width=300, height=600, cellMeters=0.5 데이터를 같은 코드로 사용합니다. x는 동쪽, y는 북쪽이고 Three.js 좌표는 `(x, 0, -y)`입니다.

다른 툴은 기존 `/maps/forest150/manifest.json`을 읽고 새 revision의 모델과 navigation을 함께 로드하면 됩니다. `sizeMeters`는 호환용 너비 값으로 남겨두었으므로, 세로 길이를 sizeMeters로 추정하지 말고 widthMeters/lengthMeters 또는 마스크 width/height × cellMeters를 사용하세요.

## 검증

- 평지 39,657셀의 연결 확인.
- 시작점에서 네 구간과 최북단 목표까지의 경로 확인.
- 몬스터 생성 12곳과 끝 지점까지의 경로 확인. y>150m인 확장 구간 포함.
- 큰 이동 입력 60건, 캐릭터 반경과 맵 바깥 경계 차단 확인.
- 매 행의 평지가 하나의 연결 구간인지 확인해 분리된 스폰 영역이 없음을 검증했습니다.
- 최종 Blender 전체/가까운 시점 렌더 확인. 두 GLB 모두 x=0~150m, 북쪽=0~300m, 평지 높이=0m(부동소수점 오차 이내) 확인.
- 전체 프로젝트 TypeScript `tsc --noEmit` 통과.
- 브라우저에서 직사각형 미니맵, 전체/캐릭터 시점, 정화 전후, 마스크, 몬스터 12마리 생성·추적 확인.
- 내비게이션 소스 SHA256은 작업 전후 동일: `0283F26816B620AB4C1998828931B24E02C5140A5FA8DF57F8DCD709FB3DB405`.
- 목표가 정지했을 때 같은 경로를 반복 계산하지 않도록 툴의 추적 갱신 조건만 개선했습니다.
- 현 PC 내장 브라우저의 캐릭터 시점에서 약 37~44 FPS 관찰. 기기별 성능 보장을 뜻하지 않습니다.

## 결과 자산과 백업

- 정화 후 GLB 5,544,640바이트 / 1,524,736삼각형, 정화 전 5,469,688바이트 / 901,936삼각형. 전체 자산 수치이며 플레이 화면에는 일부 공간 청크만 그립니다.
- 나무 3,023개, 관목 4,407개, 작은 바위 1,281개, 낮은 꽃 군락 2,434개, 큰 바위 군락 7곳, 통나무 3곳.
- 변경 전 연결 파일 백업: `_backups/20260927_forest150_to_150x300_082938`. v1 모델과 원본은 기존 release/art-source 폴더에 유지.
- 배포한 v2 파일은 생성 결과와 SHA256 일치를 확인했습니다.
- Blender의 썸네일/확장 캐시 경고는 있었으나 모델 저장·GLB 내보내기·렌더는 모두 성공 종료했습니다.

## 하지 않은 일

- 본편 레이드 전투에 대한 연결, 웨이브 규칙과 몬스터끼리의 회피.
- 타깃 모바일 기기의 성능 보장. GLB 반복 메시 인스턴싱과 공간 단위 컬링을 사용하며, 기기별 최적화는 별도입니다.
