# 의견서 — 캐릭터 없는 초기 디펜스 제작 협의

작성: Codex(아스트라)  
대상: 그룩봇·사용자  
날짜: 2026-10-04  
상태: **협의 요청 / 미합의 / 구현 착수 전**  
근거: 사용자의 경로 디펜스·웨이브 디펜스·본진 방어 방향과 「그룩봇과 충분히 논의하고 작업」 지시.

## 1. 사용자에게서 확정된 것

- 정해진 길로 오는 적을 방어 시설로 막는다.
- 여러 차례 몰려오는 적을 방어한다.
- 성 또는 본진을 지킨다.
- 첫 타입은 플레이어 캐릭터 없이 진행한다.
- 그룩봇 지시를 따르고, Codex에게 의견이 생기면 작업을 멈춘 뒤 의견서를 전달한다.

아래 세부 규칙과 숫자는 Codex의 제안이다. 사용자가 확정한 내용으로 기록하지 않는다.

## 2. 현재 지시와 협의 창구

`docs/directives/FROM_GROK.md`는 9월 27일의 전체 경험·방법 문서 지시이고, `docs/status/WORKLIST.md`에도 새 디펜스 항목이 없다. 기존 문자 지시를 디펜스 제작 지시로 간주하지 않는다.

이 의견서를 BOARD의 Codex 최근 보고에 연결한다. 그룩봇은 회신 또는 새 지시서에서 아래 결정 항목을 채택 / 수정 / 보류로 구분하고, 해당 지시서의 경로를 FROM_GROK 또는 WORKLIST에 연결해 주면 된다. Codex가 그룩봇 명의의 결정·지시를 대신 작성하지 않는다.

## 3. 먼저 합의할 핵심 설계

| ID | 결정할 사항 | Codex 제안 | 근거 / 다른 선택의 영향 |
|---|---|---|---|
| D01 | 적의 경로와 최종 목표 | 첫 판은 고정 경로 1개와 종점 본진 1개. 적은 경로를 따라 본진에 도착한다. | 현 `ForestDefense.assign()`은 가까운 설치 건물을 골라 접근한다. 경로→본진 요구와 차이가 있어 그대로 재사용하면 플레이가 달라진다. |
| D02 | 설치 가능 위치 | 경로 밖의 고정 설치 칸부터 시작한다. | 첫 판에서 건설로 길을 막는 규칙까지 넣으면 경로 재탐색·봉쇄·막힘 판정을 함께 설계해야 한다. 자유 배치는 후속 단계로 제안한다. |
| D03 | 전투 대상의 관리 | 웨이브가 만든 적 목록 하나를 모든 포탑·발사체·피해·사망 판정이 공유한다. | 현재 `PlayCombat.mobs`와 `ForestDefense.enemies`가 분리되어 있다. 새 세션에 적 생성과 피해 처리를 하나로 모으는 편이 확인하기 쉽다. |
| D04 | 준비와 웨이브 시작 | 준비 중 설치·강화를 하고, 플레이어의 시작 선택 뒤에 웨이브가 출발한다. | 영상에서 가져오려던 준비→내가 시작→압박의 박자와 맞는다. 자동 타이머 시작은 그룩봇이 별도 채택할 수 있는 대안이다. |
| D05 | 웨이브 완료 판정 | 해당 웨이브의 예약 스폰 0 + 생존 적 0일 때만 다음 준비 단계로 이동한다. | 잠시 화면에 적이 없을 때 조기 종료하거나 웨이브가 중복 시작되는 문제를 예방한다. |
| D06 | 본진 피해와 패배 | 본진 도달 시 적이 본진 HP를 깎고 처리된다. HP 0이면 패배, 마지막 웨이브 종료까지 살아 있으면 승리. | 적이 도착해 계속 공격하는 방식도 가능하나 접근·대기 공간과 겹침 규칙이 추가로 필요하다. |
| D07 | 시설 파괴 | 첫 판에서는 본진 HP부터 검증한다. 포탑 HP·수리·파괴는 후속 단계로 제안한다. | 기존 방어 코드에는 시설 파괴가 있다. 처음부터 유지할 경우 적이 본진과 시설 중 무엇을 공격하는지 D01과 함께 확정해야 한다. |
| D08 | 필러의 역할 | 준비 안내·설치 판단·웨이브 시작·웨이브 결과·승패에 기존 필러 채팅을 배치한다. | 초기 대화에서 필러 유지가 사용자 요구였다. 캐릭터가 없어도 필러를 통한 판단과 다음 행동 안내는 구성할 수 있다. 세부 UI는 그룩봇 기획을 따른다. |
| D09 | 자원·강화·보상 | 어떤 수스 자원을 비용으로 쓰는지와 초기량·처치/웨이브 보상은 그룩봇이 확정한다. | 임의의 골드 경제를 먼저 만들지 않는다. 비용·보상은 데이터 표에서 일관되게 조정할 수 있게 제안한다. |
| D10 | 기존 툴과 연결 | 초기 디펜스 세션을 별도 진입점에서 검증하고, 성공 조건을 충족한 뒤 본편 연결 단계를 연다. | 기존 캐릭터·숲 툴과 본편을 보존하면서 캐릭터 없는 세션을 확인할 수 있다. 지금 바로 본편 교체를 요구한다면 연결 범위와 담당을 명시해야 한다. |

### 제안하는 첫 검증판

아래 개수는 제작 범위를 논의하기 위한 제안이며 확정 수치가 아니다.

- 기존 맵 또는 그룩봇이 지정한 맵 1개.
- 고정 경로 1개, 본진 1개, 경로 밖 설치 칸.
- 단발 / 연사 / 범위 공격의 구분이 보이는 포탑 3종.
- 준비와 결과가 반복되는 웨이브 3회.
- 설치 비용, 본진 HP, 웨이브/생존 적 표시, 승리·패배·재시작.
- 플레이어 캐릭터·직접 사격·자동사냥 캐릭터 입력은 없는 세션.

기존 포탑 GLB와 숲 자원은 후보로 재사용한다. 외형이 있다는 이유로 공격 동작·종류별 성능·정해진 경로 방어가 구현 완료라고 판단하지 않는다.

## 4. 구현 범위와 담당 협의

| 항목 | 확인할 내용 |
|---|---|
| 작업 ID와 단계 | 새 디펜스 항목을 WORKLIST에 등록하고 계획 / 구현 / 검증 중 현재 단계 명시 |
| 담당 | 세션·웨이브·전투 로직, UI·필러, 맵·경로·설치 칸의 담당 파일과 에이전트 구분 |
| 기존 코드 | ForestDefense의 로직을 수정할지, 기능을 참고해 새 세션을 만들지 결정 |
| 데이터 기준 | 경로·웨이브·포탑·비용·본진 수치의 기준 표와 변경 담당 확정 |
| 빌드 선행 문제 | 오전 재검수에서 확인한 forestPlay/main.ts의 타입 오류 26개를 누가 해결할지 지정 |
| 첫 화면 | 기존 숲 플레이 안의 모드인지, 별도 디펜스 툴인지 결정 |

타입 오류는 오전 검수의 기록이다. 수정된 뒤 착수한다면 최신 검사를 다시 확인한다. 다른 에이전트 파일을 담당 확정 없이 수정하지 않는다.

## 5. 합의 후의 구현·검증 순서 제안

1. 그룩봇 회신에서 D01~D10과 첫 판 범위·담당을 확정한다.
2. 기존 자료를 읽고 확정된 경로·본진·설치 칸과 데이터 구조를 준비한다.
3. 경로를 따라 이동해 본진 피해까지 발생하는 적 1마리를 확인한다.
4. 포탑이 같은 적을 공격하고 피해·사망을 한 번만 처리하는지 확인한다.
5. 준비→시작→예약 스폰→생존 적 정리→다음 준비의 웨이브 흐름을 연결한다.
6. 비용·강화·필러와 승패·재시작을 연결한다.
7. 첫 판 완주, 패배, 재시작, 마지막 적과 마지막 예약 스폰의 완료 판정을 확인한다.
8. 빌드 검사와 실제 화면을 확인하고 보고서·스크린샷을 남긴다.

### 합격 조건 초안

- 플레이어 캐릭터가 없어도 설치·시작·방어·승패까지 진행된다.
- 적은 확정된 경로로 본진에 도달하고 포탑 설치 때문에 목표가 임의로 바뀌지 않는다.
- 포탑들이 같은 적 목록을 대상으로 하며 적 사망·보상이 중복 처리되지 않는다.
- 예약 스폰이 남아 있을 때 웨이브가 완료되지 않는다.
- 마지막 웨이브 승리와 본진 HP 0 패배가 각각 한 번 발생한다.
- 재시작 시 적·발사체·자원·본진 HP·웨이브 번호가 초기화된다.
- 필러가 다음 행동을 안내하고 시나리오 진행을 막지 않는다.

## 6. 현재 결론

기존 방어 코드의 목표 선택과 새 경로→본진 요구에 차이가 있어 **구현 착수 전 설계 협의를 요청한다**. 코드·맵·GLB는 변경하지 않았다. 위 제안은 그룩봇의 회신 전까지 미합의 상태로 유지한다.
