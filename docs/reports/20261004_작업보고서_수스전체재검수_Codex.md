### 3.1 캐릭터 데이터

GLB의 JSON 청크·인덱스 수·애니메이션 배열을 직접 읽었다. 삼각형은 GLB에 들어 있는 전체 메시 기준이며, 모든 메시가 동시에 보이는 수와 같지는 않다.

| 캐릭터 | 파일 | 약 MB (10진) | 삼각형 | 클립 |
|---|---|---:|---:|---:|
| 루온 기존 | `data/tools/unit_lab/character/A/wanderer_A.glb` | 9.91 | 88,618 | 18 |
| 루온 3.5 | `data/tools/unit_lab/character/Ruon_35/ruon_35.glb` | 9.92 | 88,618 | 18 |
| 리아 기존 | `data/tools/unit_lab/character/D/wanderer_D.glb` | 10.24 | 91,770 | 18 |
| 리아 3.5 | `data/tools/unit_lab/character/D_35/wanderer_D_35.glb` | 10.23 | 91,770 | 18 |
| 고양이 BCAT02 | `data/tools/unit_lab/pets/block_cat/block_cat.glb` | 1.10 | 6,452 | 6 |

사람의 공통 클립은 `idle`, `walk`, `run`, `shoot`, `shoot2`, `throw`, `walk_shoot`, `walk_throw`, `walk_gun`, `draw`, `holster`, `draw_launcher`, `holster_launcher`, `blink`, `squint`, `bow`, `wave`, `victory`이다.

고양이는 `walk`, `idle_sit`, `idle_look`, `attack_laser`, `stand_up`, `sit_down`을 가진다. 현재 `src/tools/forestPlay/PlayPet.ts`는 따라가기 중 `walk`와 `idle_sit`을 선택한다. 전환·공격 클립의 존재와 숲에서의 사용 완료는 별도다.

브라우저에서 루온 3.5와 리아 3.5를 직접 선택해 로딩과 표시를 확인했고, 리아의 바주카 단발(`shoot2`) 선택 화면도 저장했다. 숲에서는 루온 기존 비율과 고양이를 확인했다. 네 캐릭터의 18개 동작을 모두 처음부터 끝까지 재생해 검수한 것은 아니다.

### 3.2 숲·배경·리소스

- 현재 숲 manifest 리비전: `forest150x300-v7`, 크기 150×300m.
- 지형: `data/maps/forest150/releases/v7/`.
- 내비게이션·설치 칸: `data/maps/forest150/releases/v3/`의 navigation / construction / walkability.
- 정화 3단계의 조명·안개·하늘 이미지 설정은 존재하고 툴 버튼으로 전환된다.
- `mid`는 별도 중간 지형 GLB 대신 `forest_purified.glb`를 공유한다. 따라서 현재 중간 단계는 조명·하늘 차이를 포함한 표시 단계이며, 독립된 중간 지형을 확인한 것으로 기록하지 않는다.
- 숲 manifest, v7 catalog, 블록 맵 manifest의 파일 참조 112건을 검사했고 누락은 0건이었다.
- `units_free.json` 99개 항목의 GLB를 검사했고 누락은 0건이었다. 이 결과는 해당 목록의 경로 검사이며 프로젝트 전체 파일의 완전성 보증은 아니다.

### 3.3 숲 자동사냥·건설

`src/tools/forestPlay/`는 별도 개발 툴의 플레이 코드다. `PlayCharacter`, `PlayCombat`, `PlayBuild`, `PlayPet`, 카메라와 내비게이션을 함께 사용한다.

- 실제 자동사냥에서 적 11마리가 생성되고 생존 수가 6으로 감소하는 것을 확인했다.
- STOP 이후 적 6마리가 남고 플레이어가 대기로 돌아가는 것을 확인했다.
- 고양이 생성 후 클립 6개와 따라가기 ON 표시를 확인했다.
- 건설 데모에서 포탑 5종을 설치한 후 시설 5종을 추가해 설치 수 10/10을 확인했다.
- 적 재생성, 무기별 동작 전환, 이동·길찾기 로직은 소스에 있다. 이번 검수에서는 전멸 후 재생성까지의 전체 반복을 새로 완주하지 않았다.

연결할 부분도 있다. `PlayCombat.mobs`와 `PlayBuild`가 사용하는 `ForestDefense.enemies`는 각각 별도의 적 목록·HP·전투 처리를 가진다. 설치 방어와 플레이어 자동사냥이 같은 적을 대상으로 한 전투로 통합되었다고 판정할 수 없다. `src/maps/forest150/ForestDefense.ts`의 포탑 공격은 현재 공통 피해 9 / 간격 0.85초 규칙이고, 유닛랩의 개별 무기 애니메이션·공격 특성이 이 방어 루프에 모두 적용된 상태도 아니다.

숲 툴에는 본편 필러·구출·스킬 선택·보상·게임 종료를 이어주는 전체 시나리오 흐름이 확인되지 않았다. 정화 단계도 현재 수동 선택 검증이다. 이 툴을 곧바로 완성된 한 판이라고 부르면 진행 상태를 과대평가하게 된다.

### 3.4 기존 본편과 전진 웨이브

- 본편 진입점은 `index.html` / `src/main.ts`이고, 여행 화면은 `src/stage/world3d/Journey3DView.ts`다.
- `Journey3DView.ts`는 현재도 `loadActorSprite("wanderer", ...)`를 사용한다. 새 루온·리아 GLB와 숲 플레이가 본편의 캐릭터·맵으로 교체된 상태는 확인되지 않았다.
- 실제 본편에서 로비 → 외출 → 들판 i21 → 「더 모은다 / 바로 간다」 필러를 확인했고, 바로 가기 후 정화제 획득·얼룩 정화의 초반 진행을 확인했다.
- 본편의 정화·구출·기억·스킬 관련 코드와 CSV는 존재한다. 특히 `runMemoryBattleFlow()`는 `src/main.ts`에 구현과 호출이 있으므로 옛 문서만 보고 기억 전투를 미구현이라고 판정하면 안 된다. 전체 기억 전투 실행은 이번 검수 범위에서 완주하지 않았다.
- 현재 읽힌 i21 설정의 주요 수치는 얼룩 3 / 오염 5 / 벌레 12 / 원흉 HP 6이다. 이전 기획에 나온 원흉 10발과 혼동하지 않아야 한다.
- `data/forward_wave/`의 웨이브·스킬 등 CSV 13종은 존재한다. 하지만 현재 `forward-wave-tool.html`의 진입은 자동사냥 준비 화면이며 `view3d.ts` 경로를 사용한다. CSV와 10웨이브 전체 기획이 현재 진입 경로에 모두 연결되어 실행된다는 증거는 확보되지 않았다.

새 숲 툴에서 보이는 자동사냥과 기존 본편의 필러/정화가 각각 작동한다. 이 둘을 사용자가 기대하는 같은 한 판으로 잇는 작업이 다음 구현 단계다.

### 빌드 검사 방법

실행한 명령:

```text
node node_modules/typescript/bin/tsc --noEmit --incremental false --pretty false
```

결과: 종료 코드 2, 오류 26개. 실제 출력은 [typecheck.txt](assets/20261004_수스전체재검수_Codex/typecheck.txt)에 보관했다.

`package.json`의 build는 `tsc -b && vite build && node scripts/prune-dist-public.mjs` 순서다. 타입 검사 실패를 확인했으므로 전체 `npm run build`나 배포 산출물 생성을 별도로 실행하지 않았다. 개발 서버에서 화면이 표시되는 것과 정식 빌드 통과는 다르다.

## 5. 진행 기록과 현재 소스의 차이

- 캐릭터·유닛랩 정리와 제작 인계는 9월 27일 보고서에 기록되어 있다.
- 숲 플레이 애니·무기 조정은 9월 29일 보고서에 기록되어 있다.
- 10월 2~3일 최근 보고 중 일부는 그룩 목록 확인 보고여서 기능 제작의 최신 상태를 대표하지 않는다.
- 검수 중에도 숲 플레이 소스가 다른 프로세스에 의해 갱신됐다. 최종 스냅샷에서 `main.ts` / `PlayCombat.ts`는 **10월 4일 08:16**, `PlayCamera.ts`는 **08:06** 수정본이다. 코드 갱신 후 화면을 다시 대조했다.
- WORKLIST의 WA-01 대기 표시는 이미 존재하는 루온 제작물·3.5등신·제작 인계와 맞지 않는다. 다른 에이전트 담당 상태를 이번 검수에서 임의로 수정하지 않았다.
- 일부 옛 GDD는 기억 전투를 계획 단계로 쓰거나 노드 수를 이전 값으로 표기한다. 현재 소스·CSV를 함께 봐야 한다.
- 검수 중 HMR로 본편 실행이 초기화되었다. 이 때문에 짧은 진입·초반 정화 검증과 전체 클리어 검증을 구분했다.

- 숲 자동사냥 전멸 → 재생성의 반복 완주와 전체 10웨이브 / 스킬 성장.
- 모바일 목표 기기·다수 유닛 상황의 성능 측정. 여러 브라우저 탭이 열린 상태의 화면 FPS를 성능 합격 기준으로 사용하지 않았다.
- 코드 수정, 모델 재제작, 기획 변경, 커밋·푸시, CodexPack 복사본 수정.
- 그룩 문서에 남은 다른 제작 지시의 신규 착수. 이번 작업은 사용자의 직접 재검수 요청이다.

## 8. 다음 작업 순서와 막힌 질문

권장 순서: **타입 검사 통과 → 새 숲 플레이와 본편의 전투 대상·진행 흐름 통합 → 필러·설치·스킬·구출·정화 3단계가 이어지는 한 판 완주 → 목표 기기 성능 확인**.

검수 완료에 필요한 사용자 질문은 없다. 이 보고서는 다음 구현의 착수 지시나 변경 승인을 대신하지 않는다.
