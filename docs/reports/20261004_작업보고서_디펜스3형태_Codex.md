# 작업 보고서 — 숲 디펜스 세 형태

작성: Codex(아스트라)  
날짜: 2026-10-04  
상태: 구현·타입·로직 확인 / 브라우저 화면 검증과 툴 스크린샷은 접근 권한 응답 대기

## 한 줄

기존 숲 플레이 툴에 캐릭터 없는 타워·웨이브·기지 방어 관찰 모드를 연결했다. 그룩봇의 45초 / 20초×3 + 사이5초×2 / 60초 조건과 적 공격에 의한 시설 붕괴를 적용했다.

## 바꾼 파일

- `src/tools/forestPlay/DefenseSession.ts`: 고정 길, 공통 적 목록, 포탑 발사체 피해, 적 공격, 시설 HP, 모드 시간, 웨이브 간격, 일시정지.
- `src/tools/forestPlay/DefensePreview.ts`: 기존 모델 10개, 북쪽 길 표시, 시설 HP, 붕괴·사격·공격 FX, 카메라, 모드 선택과 다시보기.
- `src/tools/forestPlay/main.ts`: 필요한 import·초기화·tick 연결과 디버그 콜백의 타입 명시. 기존 소스는 보고서 assets/source_before에 백업.
- `scripts/verify_defense_modes.mjs`: 실제 navigation / construction 데이터를 사용한 로직 검증.
- `docs/reports/assets/20261004_디펜스3형태_Codex/logic_checks.json` / `source_change.json`.

## 구현 범위

- 새 HTML 진입점 없이 기존 `forest-play-tool.html`의 디펜스 버튼으로 관찰한다. 본편과 forest-map은 변경하지 않았다.
- 포탑 5, 방어물 4, 남쪽 본진 1. 기존 GLB의 색·형태는 그대로 사용한다.
- 적은 북쪽 고정 길을 따라 남쪽으로 진행하고 길 옆 시설을 순서대로 공격한다. 가까운 건물을 새 목적지로 고르는 기존 AI를 그대로 쓰지 않았다.
- 스폰·포탑 피해·적 사망은 한 세션의 적 목록에서 처리한다. 시간으로 시설 HP를 깎지 않는다.
- 초기 세 모드에는 캐릭터와 승패가 없다. 캐릭터가 들어온 뒤의 본진 승패는 후속 범위다.
- 시설 체력·공격 수치는 관찰용 초기값이며 본게임 밸런스 확정 수치가 아니다.

## 검증

- 타입 검사 통과: `node node_modules/typescript/bin/tsc --noEmit --incremental false --pretty false` (종료 0).
- 로직 검사 통과: `node scripts/verify_defense_modes.mjs`.
- 실제 길 길이 약 258.25m, navigation에서 경로 통과 가능 확인.
- 타워45초 / 웨이브70초 / 기지60초 종료와 일시정지 확인.
- 적 스폰이 없는 상태에서 시간이 지나도 시설 HP 유지.
- 세 모드에서 실제 적 공격으로 10시설이 순서대로 파괴되고 같은 파괴가 중복 처리되지 않음.
- 포탑에 의한 적 처치 발생, 웨이브 사이 5초의 스폰 중단 확인.

## 화면 검증 제한

브라우저 도구가 `http://127.0.0.1:5179` 접근을 거부했다. 우회하지 않고 사용자에게 접근 허용을 요청했다. 실제 브라우저 실행·툴 스크린샷을 확보했다고 기록하지 않는다. 코드와 로직 검증만으로 화면 품질까지 합격으로 판정하지 않는다.

## 하지 않은 일 / 다음 단계

본편·필러·자원·강화·모델 색/형태 변경·커밋·푸시는 하지 않았다. 사용자 지정 순서에 따라 네 마리 복셀 펫 제작으로 이어가고, 허용 응답이 오면 디펜스와 펫의 실제 툴 화면을 확인한다.
