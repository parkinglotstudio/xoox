# 작업 보고서 — 디펜스 방향과 그룩봇 협업 규칙

작성: Codex(아스트라)  
날짜: 2026-10-04  
근거: 전체 재검수 이후 사용자가 이 대화에서 직접 전달한 새 작업 방향.

## 1. 한 줄

첫 제작 타입은 플레이어 캐릭터 없이 방어 시설과 본진으로 진행하는 게임이다. 경로를 따라 오는 적, 반복 웨이브, 본진 방어를 같은 플레이 흐름으로 만든다.

## 2. 사용자 확정 범위

1. 타워 디펜스: 정해진 길로 오는 적을 방어 시설로 막는다.
2. 웨이브 디펜스: 여러 차례 몰려오는 적을 막는다.
3. 기지 방어: 성 또는 본진을 지킨다.
4. 첫 타입에는 플레이어 캐릭터가 없다. 기존 캐릭터 제작물을 삭제하라는 지시는 아니다.
5. 그룩봇의 작업 지시를 확인해 해당 범위와 단계를 따른다.
6. Codex에게 설계 의견이 생기면 작업을 멈추고 의견서를 작성해 사용자와 그룩봇이 읽을 수 있게 전달한다.

이 직접 지시는 이전의 캐릭터 작업만 진행한다는 담당 범위보다 최신이다. 캐릭터 없는 디펜스 작업을 이전 범위 제한 때문에 거부하지 않는다.

## 3. 의견이 생겼을 때의 절차

- 진행 중인 변경을 안전하게 저장하고 해당 작업을 멈춘다.
- `docs/reports/YYYYMMDD_의견서_짧은제목_Codex.md`에 관찰 근거, 현재 지시와의 차이, 선택지, 권장안, 영향받는 파일/범위를 쓴다.
- BOARD의 Codex 행에 의견서 경로와 판단이 필요한 내용을 남긴다.
- 이 대화에도 요점을 전달한다. 사용자 또는 그룩봇의 결정이 있기 전에는 해당 설계를 임의로 바꾸지 않는다.
- 다른 에이전트의 행과 작업 파일은 보존한다. 커밋·푸시는 사용자가 요청할 때만 한다.

## 4. 현재 지시서 확인

`docs/directives/FROM_GROK.md`와 `docs/status/WORKLIST.md`를 읽었다. 현재 본문은 9월 27일의 전체 작업 경험·방법 문서 지시이고, 새 디펜스 제작 항목이나 상세 지시서는 아직 등록되어 있지 않다.

이번에 이전 경험 문서 작업을 새 디펜스 구현으로 간주해 착수하지 않았다. 새 디펜스 지시가 등록되면 사용자의 최신 방향을 기준으로 읽고, 계획 전용·승인 대기 등의 단계가 있으면 해당 단계를 따른다.

## 5. 바꾼 파일 / 하지 않은 일

- 이 보고서와 BOARD의 Codex 행만 갱신했다.
- WORKLIST, 공통 지시서, 코드·맵·GLB는 수정하지 않았다.
- 새 디펜스 게임 구현, 새 자동화 생성, 기존 정기 확인 시간대의 변경은 수행하지 않았다.

## 6. 참고 검수 결과

`docs/reports/20261004_작업보고서_수스전체재검수_Codex.md`에 현재 캐릭터·숲·건설·본편 상태와 타입 오류 26개를 기록했다. 기존 숲 방어 코드가 새 경로/웨이브/본진 디펜스 요구를 모두 충족하는 것으로 간주하지 않는다.

## 7. 막힌 질문

사용자에게 재확인할 질문은 없다. 현재 BOARD는 새 디펜스 상세 지시 확인을 위한 대기로 둔다.
