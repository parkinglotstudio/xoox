## 6. 최근 수정: 하늘 상단이 분홍색으로 잘려 보이던 현상

### 원인

- 지형이 위로 올라간 것이 아니었다. GLB 지면 높이와 맵 루트 변환은 정상이다.
- 이전 배경은 반경 190m, 높이 100m인 열린 원통이었다. `footY=65`는 이름과 달리 **원통 위쪽 높이**였다.
- 원경 이미지 위쪽 30%를 분홍 단색으로 전환하고 원통 위도 단색으로 채워, 후면 카메라에서 구름·첨탑이 잘린 듯한 넓은 띠가 나타났다.

### 현재 반영한 해결

- 원본에 `ForestSky.ts`를 추가하고 `main.ts`에서 사용한다. 숲맵에서는 `MapView.load`에 기존 배경 URL을 넘기지 않으므로 옛 원통과 이중 렌더하지 않는다.
- 카메라 중심의 구면 배경을 사용한다. 원경은 가상 원통 투영으로 지면 높이에 맞추고, 위쪽 하늘은 **기존 원경 PNG의 구름 영역을 텍스처로 샘플링**해 이어 붙인다.
- 구면 상단에는 분홍 단색 천장이 없다. 하늘 사진을 새로 생성하거나 원본 PNG를 수정한 것이 아니다.
- 원경 반경은 190m 유지, 세로 범위는 **100→180m**, 위쪽 높이는 **65→117m**로 변경했다. 기존 이미지의 35% 높이 기준선은 지면 0m에 유지한다.
- 정화 전후 모두 적용한다. 기존 상태별 원경 틴트는 유지한다.
- 카메라마다 위치·구면 크기를 갱신하여 메인 화면과 후면 미리보기 양쪽을 지원한다. 구면은 각 카메라 far clip 안에 둔다.
- 배경은 viewport당 1 draw이며, 조명·그림자·안개 계산을 하지 않는다. 실제 FPS 측정치는 아직 없다.
- 지면, 맵 GLB, 이동 마스크, 시설 배치, 본편 공용 배경 코드는 수정하지 않았다.

### 검증 완료와 남은 확인

완료:
- 원본 프로젝트 TypeScript 검사 통과.
- 원본과 복사본의 툴 전용 TypeScript 검사 통과.
- `verify-sky.cjs`: 정화/오염, 카메라 높이 전환, far plane 범위, 투영 수치, 기준 높이, dispose 및 shader 주입 검사 통과.

**아직 실제 브라우저 GPU 화면 검증 및 수정 후 스크린샷은 없다.** 기존 작업 환경의 브라우저 제어 제한 때문에 코드·수치 검증까지만 수행했다. 이를 최종 시각 검수 완료라고 보고하지 말라.

인수 후 첫 작업:
1. 원본 숲맵 툴 새로고침 후 정화 후 기본 화면과 정화 전을 각각 본다.
2. 후면 미리보기에서 사용자 스크린샷과 같은 거리 약 4.4m, 높이 약 2.6m, FOV 약 70°로 비교한다. 실제 설정 JSON 및 UI 값도 확인한다.
3. 좌우 360° 회전, 위 보기, 낮은/높은 카메라, 이동, 정화 상태 전환을 확인한다.
4. 분홍 띠·천장 잘림이 사라졌는지, 구름 연결부와 반복·첨탑 비율이 자연스러운지, 메인/미리보기 전환 시 배경이 튀지 않는지 검사한다.
5. 문제가 있으면 원본 `ForestSky.ts`와 manifest의 배경 설정만 우선 조정한다. 원경을 조정하려고 플레이 지면을 이동하지 않는다.
6. 실제 툴 화면의 정화 전후 스크린샷을 저장하고 보고한다. Blender 렌더를 인게임 스크린샷이라고 부르지 않는다.

## 7. 이미 해결한 문제와 유지할 구조

- 나무는 6종과 여러 크기·색 변형을 사용한다. 수목과 소품을 동일 크기·동일 간격으로 단순화하지 않는다.
- 가까이 갔을 때 풀·꽃 덩어리가 사라지던 문제는 중심점 거리 대신 **전체 bounding box까지의 수평 거리**로 판정하도록 수정했다. 인스턴스 bounding box/sphere도 갱신한다.
- 메인 화면과 미리보기 각각의 카메라로 가시성을 계산한다. 한 카메라의 culling 결과를 다른 화면에 그대로 쓰지 않는다.
- 후면 미리보기는 같은 Scene·Renderer를 재사용한다. 미리보기 때문에 시뮬레이션과 애니메이션을 두 번 진행하지 않는다.
- 미리보기에서는 에디터 보조 표시를 숨기고 렌더 후 복원한다.
- v6 유물 시설 15곳과 북쪽 보스존 배치는 v7에서 유지했다. 시설은 배경 장식이며 보스 전투 구현이 아니다.
- 새 석조 포탑은 240 triangles, 유닛 시설은 264 triangles다. 기존 건설 충돌 영역에 맞춰 만들었다.

## 11. 작업 완료 보고 방식

원본의 지침 파일을 확인한다. 작업 후 `C:\xoox\docs\reports`에 날짜가 있는 한국어 보고서를 남긴다. 무엇을 바꿨는지, 왜 바꿨는지, 실제 검증 결과, 미완료·미검증 항목, 백업 경로와 스크린샷 경로를 명시한다. 실패한 실행을 성공이라고 보고하지 않는다.

우선 원본 툴에서 최신 하늘 수정의 실제 화면을 확인하고, 현재 상태와 필요한 후속 수정만 간단히 보고해 달라.
