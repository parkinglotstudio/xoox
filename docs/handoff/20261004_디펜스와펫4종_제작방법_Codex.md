작성: Codex(아스트라) · 2026-10-04  
작업 루트: `C:\xoox` 원본. 커밋·푸시 없음.

## 1. 범위와 확인 수준

사용자가 그룩 회신 확인 후 직접 제작을 승인했다. 먼저 forest-play 안의 캐릭터 없는 방어 관찰 세 형태를 만들고, 별도 작업으로 사용자 제공 펫 4장을 모델링한다. 기존 캐릭터·BCAT·맵 데이터는 보존한다.

이 문서는 소스와 로컬 제작·검증 방법을 설명한다. 브라우저 도구의 `http://127.0.0.1:5179` 접근이 거부되어 실제 웹 화면·조작 검증 및 웹 툴 스크린샷은 미완료다. 보고 assets의 펫 이미지는 **Blender 모델 렌더**이며 웹 스크린샷이 아니다. 브라우저 접근 재승인 질문은 이 대화에서 대기 중이다.

## 3. 디펜스 구조

기준 문서는 `docs/handoff/20260927_숲플레이통합/DEFENSE_MODES.md`다. 같은 숲에서 북쪽 고정 길 → 남쪽 본진, 포탑 5·방어물 4·본진 1을 배치한다. 기존 시설 GLB의 형태와 배색을 사용한다. `DefenseSession`은 순수 시간·이동·공격 판정이고 `DefensePreview`는 로딩·그리기·카메라·패널이다.

- 타워: 45초. 웨이브: 20초 세 번, 사이 휴지 5초 두 번, 총 70초. 기지: 60초.
- 실제 enemy_attack 이벤트가 시설 HP를 줄인다. 시간만 흘려 HP를 깎지 않는다.
- 길을 이동하는 적 → 살아 있는 시설로 접근 → 공격 → 다음 시설 이동. 포탑은 사거리 안의 적을 자동 공격한다.
- 고정 0.05초 로직 스텝. 정지 시 시간·공격·스폰·시각 동작을 멈춘다.
- 시간 종료는 관찰 완료다. 캐릭터, 승패 판정, 자원, 강화, 필러 연결은 없다.
- UI에서 세 모드, 일시정지, 다시 보기, 전선 따라보기·전체 길, 속도 1/2/4를 선택한다.
- 공격 수치와 속도는 초기 관찰용 값이다. 본게임 난이도 검증으로 해석하지 않는다.

CLI 검증: `node scripts/verify_defense_modes.mjs`. 실제 마스크·배치를 읽어 경로, 시간 종료, 휴지기 스폰 중단, 적 공격·시설 붕괴, 정지, 중복 붕괴 방지를 확인한다. 결과는 `docs/reports/assets/20261004_디펜스3형태_Codex/logic_checks.json`이다.

## 4. 펫을 만든 방법 — 재현 순서

### 입력과 모델 구분

입력은 사용자 Downloads의 네 그림이다. `data/tools/unit_lab/pets/{id}/reference.png`에 원본을 복사해 같은 툴에 표시한다. 사진이나 이미지에서 자동 3D 추출한 모델이 아니다. **그림의 특징을 좌표·형상·배색으로 직접 설계한 Blender 복셀 모델**이다. 단일 그림에 없는 후면과 관절 구조는 그림의 장비·색을 이어서 설계했다.

| id | 표시 이름 | 특히 반영한 요소 |
|---|---|---|
| nofilter | NoFilter (파일명 기준 임시 표시) | 황금 몸체, 민트 눈/귀, 회색 주둥이, 복숭아색 바이저/목줄, 기계 관절 |
| flux | Flux | 크림색 이마/갈기, 분홍 장갑과 머리 볏, 노란 귀 슬랫/발톱, 측면 배선 |
| lumos | Lumos | 밝은 털, 비대칭 기계 얼굴과 붉은 슬롯, 금속 앞다리, 붉은 발 |
| gizmo | Gizmo | 고양이 짧은 주둥이, 청록 긴 갈기, 황동 이마 장식, 분홍 눈동자, 등 장치/기계 꼬리 |

기존 BCAT를 새 색으로 칠한 변형이 아니다. 새 형상은 `scripts/unit_lab_pets4/build_pets4.py`의 `sculpt()`에 따로 작성했다. BCAT의 절대 관절 행렬·IK·NLA export 방법을 참고했다.

### 형상 → 복셀 → 메시

1. `Volume`은 본별로 0.02m 고정 격자를 만든다. `box`, `ell`, `poly`, `segment`로 몸·머리·귀·눈·장비·털을 채운다.
2. 같은 본에서 나중에 추가한 색/형상이 해당 격자를 덮어쓴다. 눈 소켓·눈동자·바이저는 머리 격자에, 귀는 귀 본에, 다리 장갑은 대응 다리 본에 붙인다.
3. 격자 내부 면을 제거하고 노출된 면만 남긴다. 같은 색/발광 속성의 인접 면을 직사각형으로 합친다(그리디 메시).
4. 본별 경계에는 캡을 남겨 움직일 때 빈 구멍을 만들지 않는다. 각 면의 꼭짓점은 한 본에 가중치 1을 갖는다.
5. 최종 **하나의 스킨 메시**에 불투명·발광 두 재질을 쓴다. GLTFLoader에서는 재질별 2개 skin primitive로 나뉠 수 있다. 큐브 수만 개를 각각 Object로 생성하거나 프레임마다 복셀화하지 않는다.
6. sRGB 팔레트를 선형 색으로 바꿔 Color vertex attribute에 기록한다. 발광도 같은 vertex color를 사용한다. 외부 텍스처 의존성은 없다.

크기를 더 잘게 하면 셀 수·노출 면·내보낸 데이터가 늘어난다. 현재 0.02m는 이 첫 버전의 선택이며 모바일 성능 검증값이 아니다. 많은 개체를 동시에 쓰려면 저해상도 LOD와 별도 부하 측정이 필요하다.

### 리깅과 동작

29본: root/pelvis/spine/chest/neck/head/jaw, 좌우 귀, 앞·뒷다리 upper/lower/paw 각 좌우, 꼬리 8개. 정면은 Blender -Y, 내보낸 glTF 정면은 +Z다. bone 이름의 점은 Three.js에서 제거될 수 있어 `front_paw.L` 대신 `front_pawL`로 조회한다.

- 몸통·머리의 세계 변형 행렬을 먼저 만든 뒤 rest 및 부모 행렬로 pose basis를 구한다. 축 부호를 임의로 뒤집어 맞추지 않는다.
- 앞·뒷다리는 두 관절 IK. 보폭에 비해 다리 길이가 모자라 관절이 떨어지는 문제를 막도록 휴지 관절을 약간 굽힌 구조로 만들었다.
- 걷기는 대각선 보행, 달리기는 앞다리/뒷다리 위상과 보폭·발 들기·머리 반응을 구분한다.
- 앉기·일어서기는 pelvis가 내려가고 뒷발을 순서대로 옮기는 smoothstep 전환이다. 툴에서 앉은 동작↔선 동작을 고르면 전환 클립 후 요청한 루프에 들어간다.
- 귀·꼬리 끝에 작은 위상차를 주어 idle/걷기/달리기에서 조금씩 움직인다.
- 30fps로 본 위치·쿼터니언·스케일 키를 굽고, 클립별 NLA track을 만든다.

| 클립 | 시간 | 재생 |
|---|---:|---|
| idle_stand | 4초 | 루프 |
| idle_sit | 4초 | 루프 |
| idle_look | 5초 | 루프 |
| walk | 1초 | 루프 |
| run | 0.6초 | 루프 |
| attack_laser | 0.7초 | 단회, 툴에서 3초마다 반복 |
| stand_up | 1.1초 | 단회 → 서기/요청 동작 |
| sit_down | 1.1초 | 단회 → 앉기/요청 동작 |

달리기는 in-place다. manifest의 walk 1.3m/s·run 3.8m/s는 게임 연결 시 사용할 기준 제안이고 실제 이동 코드는 이번 범위에 없다. 눈 레이저의 소켓은 head local 좌표로 manifest/GLB extras에 기록한다. 런타임은 head.localToWorld로 시작점을 구한다. BCAT에 달리기를 새로 덮어쓰지 않았으므로 기존 BCAT 선택에서는 달리기 버튼이 비활성화된다.

## 5. 검증·산출물

모델러 내부 검증은 루프 양 끝의 모든 본 변형 행렬, 앉기↔서기 endpoint, 여러 중간 포즈의 바닥 침범 및 관절 접합을 검사한다. `verify_pets4.mjs`는 내보낸 GLB를 Three GLTFLoader로 다시 읽고 8개 클립·29본·스킨 가중치·삼각형·재질·걷기 대비 달리기 보폭/주기·파일 존재·변형된 bounds를 확인한다.

`verify_defense_pet_build.mjs`는 두 새/수정 툴만 별도 production-check 폴더에 빌드한다. 실제 dist와 대용량 public 데이터에는 손대지 않는다. 이는 웹 실행·WebGL·FPS 검증을 대신하지 않는다.

보고 이미지/로그/검증: `docs/reports/assets/20261004_펫4종_Codex/`. `reference_comparison.png`, `pose_comparison.png`, `pets4_overview.png`, `run_loop.gif`는 Blender 렌더를 모은 검토 자료다.
