## 2. Phase 1 — 채팅 패널을 오른쪽 소형 패널로

### 2-1. 목표
`25` §3 / `26` §1~2 그대로. 새 데이터·새 시스템 없음, **레이아웃 CSS + 컨테이너 구조만** 변경.

### 2-2. 작업 항목 (아래 §6 태스크 목록과 1:1 대응)

1. `index.html`의 `#app` 하위 최상위 레이아웃을 세로 flex-column에서 **가로 2분할**(메인 영역 + 우측 패널)로 변경할 지점 확인
2. `.feed`를 우측 패널 폭(잠정 30~35%, `25` §9-2 결정사항)으로 축소하는 CSS 작성
3. 카드 정렬 규칙 추가: 화자 있는 카드(코멘터리)=왼쪽 정렬+아이콘, 시스템/전투 로그=오른쪽 정렬 또는 중앙(`26` §2)
4. `syncFeedBottomPad` 등 기존 스크롤/패딩 로직이 새 폭에서도 깨지지 않는지 확인
5. 좌측(메인) 영역은 Phase 1 시점엔 **기존 상단 상태뷰를 그대로 두는 임시 상태**로 둔다(탐방 뷰는 Phase 2) — 빈 공간 방치 금지, 임시 배치 결정 필요

### 2-3. 완료 기준
- 로그가 오른쪽 소형 패널에서 정상 표시·스크롤됨
- 기존 게임 로직(구조 조우, 전투, 커맨터리) 전부 정상 동작(로그 위치만 바뀜)
- `npm run build` 통과, 실제 플레이로 최소 1일차~구조 조우 1회 확인

### 7-2. Phase 1 — 1차 시도 실패 → 가로 전환 후 완료

| 단계 | 결과 |
|---|---|
| 1차 시도(세로 유지) | **실패.** 채팅 패널 폭 147px → 카드 텍스트 7~8자/줄, 127자 나레이션이 11줄. 판독 불가 |
| 원인 | 기획 단계에서 **채팅 패널의 최소 가독 폭을 계산하지 않음**. 세로 420px 프레임에 사이드 패널은 구조적으로 불가 |
| 조치 | 27번 문서의 "가로 재검토 트리거" 발동 → 지시자 확인 후 **가로 모드 확정** |
| 2차(가로) | **완료.** 프레임 1000×480, 채팅 350px, **26자/줄** |

### 7-2b. 지시자 조정 3회 (레이아웃 최종 형태까지)

가로 전환 후 지시자 피드백으로 레이아웃이 세 번 더 바뀌었다. **좌우 분할 → 상하 2단 + 오버레이**가 최종.

| 회차 | 지시 | 결과 |
|---|---|---|
| 1 | "하단을 길게, 오른쪽 채팅을 화면과 같은 비율 높이로, 하단 버튼 부분을 정보로 꽉 차게" | 타임라인을 메인 컬럼 안으로 옮겨 채팅이 전체 높이 확보 · statbar/currency를 `.controls` 안으로 흡수해 하단바 105→152px |
| 2 | "연출 화면과 채팅 글자를 오버랩" → (테스트 후) "**상단 연출 / 하단 버튼으로 상하 구별**" | 좌우 컬럼 분할 **폐기**. `.controls`를 static으로 되돌려 상하 2단, 채팅은 상단 구간 안 우측 반투명 오버레이(`backdrop-filter: blur(7px)`) |
| 3 | "채팅 폰트·창 2/3 축소 + 왼쪽 정렬 / 타임라인도 배경에 오버랩해 상단 배경 꽉 채우기" | `--chat-w` 291→191px, 본문 13.5→9px, 전 카드 왼쪽 정렬 · `.day-roadmap`을 absolute 오버레이로 전환 → 배경이 상단 0px부터 참 |

**여기서 얻은 것:** 레이아웃은 문서상 합의보다 **실제로 띄워 보고 나서** 방향이 바뀌는 폭이 크다. 초안을 정교하게 다듬는 것보다 **빨리 띄워서 보여주고 조정**하는 편이 효율적이었다.

### 7-3. 실제 변경 내역

**CSS** (`src/style.css`) — 파일 끝에 가로 오버라이드 블록 추가(기존 세로 규칙은 보존, 회귀 위험 최소화)
- `.phone` 가로 프레임(`min(100vw,1000px)` × `min(100vh,480px)`), `#app` 세로 중앙정렬
- `.visual-stage` 고정 높이(168/200/300/312) → `flex:1` (변형 클래스 전부 포함) · 전체 폭 + `padding-right: var(--chat-w)`(배경/내용 분리)
- `.game-row` = 상단 구간(`flex:1`, `position:relative`) / `.controls` = 하단 구간(`static`, 전체 폭)
- `.day-roadmap` → `absolute` 오버레이 + 아래로 페이드
- `.feed` → `absolute` 우측 오버레이, 배경 투명, 카드 `rgba(12,9,28,.58)` + `blur(7px)`, 본문 9px, 전부 왼쪽 정렬
- `--chat-w: clamp(186px,23%,253px)` — 채팅 폭 단일 출처(무대·타임라인 패딩이 참조)
- `.controls` 안에 statbar/currency 흡수 · `.controls-dock` **하단 36px 유지**(게이지 라벨 잘림 방지, 실측)

**TS** (`src/main.ts`)
- `#app` 템플릿: `.game-row` / `.main-area` 래퍼 신설, `.day-roadmap`을 `.main-area` 안으로, `.statbar`·`.currency-bar`를 `.controls` 안으로 이동
- `getControlsOverlayHeight()` 하한 120 → 72 (가로에서 도크가 낮아짐)
- `syncFeedBottomPad()` — 피드 하단 여백 제거, CSS 변수는 유지
- `scrollFeedToBottom()` — 도크 높이 보정 제거

### 7-4. 검증

`npm run build` 통과. 실제 플레이로 인트로→컷신→1일차→스킬선택→2일차 구조 조우(5턴)→미니게임까지 진행하며 상태별 넘침 전수 검사 — **전 상태 0건**. 상태별 실측치: [`26_UI_와이어프레임.md`](./26_UI_와이어프레임.md) §1-1.

**미검증 항목:** 실제 전투 플레이(레이아웃만 강제 적용해 확인), 실기기 가로 해상도.

### 7-5. 검증 방법에서 배운 것 【중요 — 다음 세션 필독】

이번에 **잘못된 검증으로 두 번 헛짚었다.** 방법을 고정한다. 상세: [`25`](./25_UI연출_리뉴얼_기획서.md) §9-1

1. **측정 전 `document.getAnimations().forEach(a=>a.finish())` 필수** — 브라우저 페인이 표시되지 않으면 CSS 애니메이션이 첫 키프레임에 멈춰, 없는 버그를 만들어낸다(카드 `scale(0.6)`, 버튼 `translateY(51px)` 오탐 사례)
2. **넘침 검사에서 스크롤 컨테이너(`#feed`) 내부 제외** — 스크롤로 올라간 카드가 오탐됨
3. **레이아웃은 구조가 아니라 최종 렌더 결과(글자수·줄수)로 판정**
4. **Bash는 절대경로 사용** — 셸 cwd가 다른 프로젝트 워크트리로 리셋돼 엉뚱한 파일을 읽은 사례 있음(371줄 vs 실제 5555줄)
