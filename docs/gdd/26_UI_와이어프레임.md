**실측 치수 (프레임 831×480 기준 · 프레임은 뷰포트에 반응, 최대 1000×480)**

### 최종 구조: 좌우 분할 ❌ → **상하 2단 + 오버레이** ✅

지시자 확정(2026-08-04):
> "상단 연출 구간 : 게임 + 오버랩 채팅 / 하단 버튼 구간 : 게임 정보 및 버튼 — 이렇게 **상하로 구별**"

중간에 좌우 컬럼 분할로 만들었다가 **폐기**했다. 최종은 화면을 위/아래로만 나누고, 상단 안에서 채팅·타임라인이 연출 위에 **겹친다**.

**레이아웃 규칙 (구현 반영)**

| 요소 | 규칙 | 비고 |
|---|---|---|
| `.phone` | `min(100vw,1000px)` × `min(100vh,480px)` · `flex-column` | 뷰포트에 반응 |
| `--chat-w` | `clamp(186px, 23%, 253px)` | **채팅 폭 단일 출처** — 무대·타임라인의 우측 패딩도 이 값을 참조 |
| **상단** `.game-row` | `flex:1` · `position:relative` | 오버레이(채팅)의 기준 컨테이너 |
| `.main-area` | `position:relative` · 전체 폭 | 타임라인 + 무대 |
| `.visual-stage` | 전체 폭 · `flex:1` · `padding-right: var(--chat-w)` | **배경은 전체 폭, 내용만 왼쪽으로** 밀어 채팅에 안 가림 |
| `.day-roadmap` | `position:absolute; top:0` · 아래로 페이드 그라디언트 | 흐름에서 빼야 배경이 0px부터 참 |
| `.feed` | `position:absolute; right:0; top:0; bottom:0` · 배경 투명 | 상단 구간 **안에서만** 겹침 |
| 채팅 카드 | `rgba(12,9,28,.58)` + `backdrop-filter: blur(7px)` | 뒤 연출이 비치되 글자는 읽힘 |
| 채팅 글자 | 본문 9px / 대사 8.5px / 화자 7.5px · **전부 왼쪽 정렬** | 폭과 함께 2/3 축소 → 줄당 20자 유지 |
| **하단** `.controls` | `position:static` · 전체 폭 · `flex-column` | 스탯행 + 게이지/버튼행 한 덩어리 |

> **핵심 제약 3가지 (건드릴 때 주의)**
> 1. `.controls`는 **흐름 배치(static)** 여야 한다 — absolute로 되돌리면 상단이 그 아래로 흘러 상하 경계가 무너진다.
> 2. `.day-roadmap`은 **absolute**여야 한다 — 흐름에 넣으면 배경이 그만큼(46~76px) 아래로 밀려 "상단 꽉 참"이 깨진다.
> 3. 무대의 **배경은 전체 폭 / 내용은 `padding-right: var(--chat-w)`** — 이 분리를 없애면 캐릭터·캡션이 채팅에 가린다.

**주의(실측으로 잡은 함정)**: `.controls-dock`의 하단 패딩을 줄이면 게이지 라벨(`대박 0/7`)이 아이콘 아래로 걸려 **잘린다**. 14px에서 20px 잘림 확인 → **36px 이상 유지**할 것.

### 1-1. 상태별 검증 결과 (2026-08-04 실측)

가로 전환 후 각 게임 상태를 실제로 띄워 `.phone` 밖 넘침을 전수 검사했다. 전 상태 **넘침 0건**.

| 상태 | 화면 구성 | 실측 | 판정 |
|---|---|---|---|
| 인트로 스플래시 | 전체화면 | 999×480 | OK |
| 진입 컷신 | 전체화면 오버레이 + 대사 박스 | 박스 360×96, 좌우 여백 320 | OK |
| 일반 일차 진행 | 상하 2단 + 채팅 오버레이 | 위 그림 | OK |
| 스킬 선택 | 전체화면 모달, 카드 3장 세로 | 카드 320×109 ×3 | OK(좌우 공백 큼→폴리시) |
| 구조 조우 | `.stage-rescue` | 무대 안 649×181 / 링 96×96 | OK |
| 미니게임(룰렛) | 전체화면 패널 | 패널 999×480, 무대 340×212 | OK |
| 전투 | `.stage-combat` | 액터 75 + 바 21 + 로그 140 | OK ※ |

※ 전투는 8일차까지 플레이가 오래 걸려 **CSS 클래스를 강제 적용해 레이아웃만 검증**했다. 실제 전투 플레이 중 검증은 미실시 — ② 착수 시 함께 확인할 것.
※ 위 실측 중 무대 관련 수치는 **좌우 분할 시절(무대 폭 649)** 값이다. 상하 2단 전환 후 무대는 전체 폭 830으로 넓어졌고 넘침 재검사에서 0건을 확인했으나, 개별 수치는 갱신되지 않았다.

## 2. 채팅 패널 상세 (①, 완료)

> **정렬 규칙이 바뀌었다.** 아래 초안은 화자=왼쪽 / 시스템=오른쪽으로 나눴으나, 최종은 **전부 왼쪽 정렬**이다(지시자 확정). 화자 구분은 정렬이 아니라 카드 스타일(코멘터리는 어두운 청록 톤 + 화자명)로 한다.

```
[초안 — 보관용]
┌─────────┐
│ 🦉 Olmas │
│ 신호가   │
│ 잡혔다.  │
│ 하수도   │
│ 지구.    │
└─────────┘
      ┌─────────┐
      │ 1일차    │  ← 시스템/구분 카드(화자 없음)는 중앙 정렬
      └─────────┘
┌─────────┐
│ 🐕‍🦺 Piper│
│ 냄새가   │
│ 난다.    │
│ 가까워.  │
└─────────┘
              ┌─────────┐
              │ ⚔ 전투   │  ← 전투 로그는 오른쪽 정렬 +
              │ 245 피해 │    다른 배경색(화자 없는 시스템성 로그)
              └─────────┘
```

- 화자 있는 카드(코멘터리) = 왼쪽 정렬 + 캐릭터 아이콘, 실제 메신저 말풍선처럼
- 시스템/전투 로그 = 오른쪽 정렬 또는 중앙, 옅은 배경으로 구분
- 자동 스크롤 하단 고정(기존 로직 재사용)

## 5. 폰 UI (④, 최종 단계) — 【가로 전환으로 재설계 필요】

> ⚠️ 아래 그림은 **세로 프레임 시절 초안**이다. 가로 확정(1000×480)으로 "세로로 긴 폰" 은유가 화면과 충돌한다 — 세로 폰을 그대로 띄우면 높이 480px 안에 앱 그리드가 다 안 들어간다. 착수 전 아래 중 하나를 택해야 한다([`25`](./25_UI연출_리뉴얼_기획서.md) §9-7):
>
> - **(A) 중앙에 세로 폰**: 은유 유지, 좌우 공백 큼, 앱 그리드 세로 압축 필요
> - **(B) 가로 태블릿형**: 화면을 꽉 씀, 은유는 "폰"에서 "단말기"로 바뀜
> - **(C) 좌측 앱 레일 + 우측 본문**: 가로에 가장 자연스러움, Coffee Talk 은유는 옅어짐

## 7-3. 전체화면 콘텐츠 전환 규격 【2026-08-05 정의·적용】

스킬선택·미니게임·컷신·각종 모달이 `display` 토글만으로 튀어나와, 상단 탐방 화면 위로 **갑자기 덮이는** 문제가 있었다. 공통 규격을 정하고 전 패널에 적용했다.

| 항목 | 값 |
|---|---|
| 등장 | **220ms** — 투명도 0→1, 8px 아래에서 상승, 0.985→1 확대 |
| 패널 내용 | 60ms 늦게 12px 상승(깊이감) |
| 뒤 화면 | `backdrop-filter: blur(4px)` — 연출이 물러남 |
| 퇴장 | **즉시**(미구현) — `display`는 애니메이션 대상이 아니라 JS에서 클래스를 먼저 붙여야 함 |
| 예외 | `.victory-panel` — 고유 연출이 있어 제외 |

**구현 요령:** `display:none` → 표시로 바뀌면 CSS 애니메이션이 자동 재생된다. 덕분에 **JS 수정 없이** 전 패널에 일괄 적용됐다.

적용 대상: 스킬선택 · 미니게임 · 컷신 · 학습스킬 · 보상 · 교체 · 악마계약 · VS · 펫버프 · **스크랩북**
