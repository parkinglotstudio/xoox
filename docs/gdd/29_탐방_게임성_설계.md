# 29. 탐방 게임성 — 자동 진행 × 수동 탐방의 조합

> 작성: 2026-08-04 · 상태: 【**§3 역할분담안 보류** · 아래 §0-1 확정안으로 대체】

> 발단: 지시자 — "하단은 자동 이동, 수동으로도 게임을 진행할 수 있는 구조", "이 두 개를 조합해서 만들 수 있는 게임성을 기획해보자"

---

## 0-1. 【확정 2026-08-05】 지시자 결정 — 메인은 건드리지 않는다

> "버튼으로 진행하면 **기존 시나리오대로** 하는 게 좋을 것 같고, **수동은 나중에 숨겨진 콘텐츠** 정도 하는 게 좋을 것 같아. 일단 이 부분은 이렇게 두고 나중에 게임성을 넣고…"

| | 확정 |
|---|---|
| 자동 진행(버튼) | **기존 시나리오 그대로.** 일차 이벤트·구조 조우 확률 스폰·전투·미니게임 전부 현행 유지 |
| 수동 탐방(맵) | **선택적 숨은 콘텐츠 전용.** 메인 진행에 필수가 아님 |
| §3의 역할 분담안 | **보류** — 특히 "구조 조우를 확률 스폰 → 맵 배치로 전환"(§6-1)은 **하지 않는다** |
| 시기 | 게임성 본격 투입은 나중. 지금은 구조만 세워둔 상태로 둠 |

**이 결정의 이점:** 기존 `rescue_spawn_chance` 로직·일차 진행·밸런스를 하나도 안 건드린다. 탐방은 순수 추가물이라 **회귀 위험 0**. 아래 §1~§7은 나중에 "게임성을 넣을 때" 다시 꺼내 볼 후보로 보존한다.

**이 결정에 따라 바뀌는 것:** 탐방 맵에 놓을 콘텐츠는 "메인에 필요한 것"이 아니라 **놓쳐도 되는 보너스**여야 한다 → 가장 잘 맞는 후보가 [22 Tigon 기억조각](./22_TIGON_기억조각.md)(수집형·선택적·서사 보상).

---

## 0. 지금 손에 있는 두 개

| | 자동 진행 (하단 버튼) | 수동 탐방 (탑뷰 맵) |
|---|---|---|
| 출신 | 카피바라고식 로그라이크 | Cozy Grove식 탐방 |
| 조작 | 「다음날」 한 번 누르면 하루가 흐름 | 맵을 탭해 원하는 곳으로 걸어감 |
| 정보 | 채팅 로그로 결과가 쌓임 | 화면에서 직접 지점을 발견 |
| 성격 | **수동적·편안함** | **능동적·발견** |
| 현 상태 | 구현됨(기존 시스템) | 구현됨(Phase 2) |

**둘 다 있는데 지금은 서로 상관이 없다.** 버튼만 눌러도 게임이 끝까지 진행되고, 탐방은 곁다리 장식이다. 여기에 관계를 만드는 것이 이 문서의 목적.

---

## 1. 설계 원칙 — 왜 굳이 조합하나

XOOX의 핵심은 **"버려진 아이를 구조한다"**([[rescue-encounter-system]]). 그런데 지금은 구조 조우가 **확률로 알아서 튀어나온다**. 버튼만 누르면 알아서 만나지므로, 플레이어는 "구했다"기보다 "만나졌다"에 가깝다.

> **핵심 제안: 구조 대상은 플레이어가 직접 찾아가야 만난다.**
> 자동 진행은 *시간을 흘려보내는 장치*, 수동 탐방은 *발견하는 장치*로 역할을 나눈다.

이러면 "모두 가족이다 — 버림받았어도"라는 주제가 **조작으로 체험**된다. 그냥 흘려보내면 놓치고, 발품을 팔아야 만난다.

## 2. 코어 루프 제안

```
   ┌──────────────────────────────────────────────┐
   │  하루 시작 — 맵에 지점들이 놓임               │
   │  (일부는 흔적/자원, 일부는 "무언가의 기척")     │
   └───────────────────┬──────────────────────────┘
                       │
        ┌──────────────┴───────────────┐
        │  플레이어 선택 (시간 안 감)     │
        │  · 맵을 돌아다니며 지점 조사     │
        │  · 위로 더 깊이 들어가 볼까      │
        └──────────────┬───────────────┘
                       │  「다음날」을 누르면
                       ▼
   ┌──────────────────────────────────────────────┐
   │  하루 경과 — 방랑자가 위로 전진(자동 이동)     │
   │  · 일차 이벤트/전투 발생(기존 시스템)          │
   │  · 조사 안 한 지점은 사라지거나 남음(§4-3)     │
   └──────────────────────────────────────────────┘
```

**핵심: 버튼을 누르기 전까지 시간은 흐르지 않는다.** 탐방은 "공짜"지만, 얻는 건 **직접 찾아간 것뿐**이다.

---

## 3. 두 축의 역할 분담 (확정 제안)

| | 자동 진행(버튼) | 수동 탐방(맵) |
|---|---|---|
| 시간 | **하루를 소모** | 소모하지 않음 |
| 담당 콘텐츠 | 메인 진행 — 일차 이벤트, 액션 전투, 보스, 스테이지 전환 | **구조 조우**, 기억 조각, 자원·흔적 |
| 놓칠 수 있나 | 아니오(반드시 겪음) | **예 — 안 가보면 못 만남** |
| 정서 | "여정은 계속된다" | "내가 찾아냈다" |

> 이렇게 나누면 **자동만 눌러도 게임은 끝까지 굴러가지만**(카피바라고식 편안함 유지), **구조는 하나도 못 한다**. 엔딩은 보되 아무도 구하지 못한 여정이 된다 — 그 자체로 XOOX다운 메시지.

---

## 4. 세부 규칙 제안

### 4-1. 위로 갈수록 깊어진다 (소프트 게이트)

지시자 의견: *"위로 더 크게 해서 나중에는 더 못 올라가게 막기는 하겠지만, 자유롭게 하는 것도 좋은 방법"*

→ **물리적 벽 대신 "갈수록 힘들어지는" 자연 제동**을 1차안으로 제안한다.

| 맵 세로 위치 | 성격 |
|---|---|
| 아래(y 70~100%) | 안전. 흔적·자원 위주 |
| 중간(y 35~70%) | 구조 대상이 나타나기 시작 |
| 위(y 0~35%) | 좋은 것도 많지만 **오염이 짙다** — 접근 시 HP/자원 압박, 조우 난도↑ |

- 하드 게이트(못 올라감)는 **필요할 때만** 추가: 구역 클리어 조건, 스토리 락 등
- 자유롭게 두되 "너무 깊이 가면 대가가 있다"는 쪽이 탐험 심리에 맞음

### 4-2. 자동 이동의 도달 지점

「다음날」을 누르면 방랑자가 위로 한 구간 전진한다(현재 구현: `journey()`). 이때:

- **이미 플레이어가 위로 올라가 있으면** 거기서 이어서 전진 → 부지런히 탐방한 만큼 진도가 빠름
- **아래에 머물렀으면** 그만큼 천천히 전진
- → **"탐방이 곧 진행"**이 되어 두 축이 자연스럽게 맞물린다

### 4-3. 지점의 수명

| 종류 | 하루가 지나면 |
|---|---|
| 흔적·자원(MEMO) | 사라짐. 새 지점이 위쪽에 생성 |
| 구조 대상 | **남음.** 단 며칠 방치하면 사라짐(놓친 아이) — 재조우 풀([[rescue-encounter-system]])과 연결 |

"오늘 안 가면 내일은 없을 수도 있다"는 압박이 탐방 동기가 된다.

### 4-4. 자동/수동 조작 구조 (지시자 요청)

- **수동**: 지금처럼 맵을 탭해 이동·조사. 「다음날」은 직접 누름
- **자동**: 하단에 **자동 진행 토글**. 켜면 「다음날」이 일정 간격으로 반복 실행되어 관전 모드가 됨(카피바라고의 방치형 감각)
- 자동 중에도 **맵 탭은 항상 살아있게** — 뭔가 발견하면 즉시 개입 가능. 개입하면 자동은 일시정지

## 6. 결정 필요 / 리스크

| # | 항목 | 메모 |
|---|---|---|
| 1 | **구조 조우를 확률 스폰 → 맵 배치로 바꿀지** | 이 문서의 최대 변경점. 기존 `rescue_spawn_chance` 로직을 대체하게 됨 |
| 2 | 지역 이동이 하루를 소모하는지 | 27번 문서 미결 사항. 이 설계에선 **소모 안 함**(탐방의 일부)을 제안 |
| 3 | 자동 진행 토글의 간격·정지 조건 | 조우·전투 시 자동 정지가 자연스러움 |
| 4 | 지점 재생성 규칙 | 하루마다 몇 개, 어디에(위쪽 편중?) |
| 5 | 깊은 곳의 "대가" 구체화 | HP 감소? 타락 게이지? 새 자원? |
| 6 | 놓친 구조 대상의 처리 | 며칠 뒤 소멸 vs 다른 구역으로 이동 |

## 7. 단계적 도입 제안 (한 번에 다 하지 않기)

```
1단계  자동/수동 토글 + "버튼 누르기 전엔 시간 안 감" 확립   [작음]
   ↓
2단계  구조 대상을 맵 지점으로 배치 (확률 스폰과 병행 운영)   [중간·핵심]
   ↓
3단계  깊이에 따른 위험/보상 곡선                          [밸런스]
   ↓
4단계  지점 수명·재생성, 놓친 아이 처리                     [운영 규칙]
```

1단계만 해도 "내가 시간을 통제한다"는 감각이 생겨 탐방이 장식에서 벗어난다.
