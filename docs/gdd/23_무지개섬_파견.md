## 0. 왜 필요한가 (빈 자리 확인)

지금 엔진(`engine.ts`)엔 이미 이런 상태가 있다:

- `state.joinedPartyMembers` — 구조로 합류한 전체 펫 목록
- `getPartySlots(data, day)` — 그 중 **전투에 실제로 쓰이는 슬롯 수**(스테이지별 2→3→4→5, `stage_map_config.party_slots`)

즉 **합류했지만 전투 슬롯엔 못 들어간 펫이 이미 존재하는데, 지금은 그냥 로스터에 앉아만 있고 아무 역할이 없다.** 무지개섬도 지금은 순수 배경 설정("눈물이 무지개가 되는 곳")일 뿐 아무 기능이 없다. 이 둘을 엮으면 새 시스템을 만들지 않고도 빈 자리를 채울 수 있다.

## 1. 벤치마크 — Cult of the Lamb의 팔로워 배치

- 구조한 동물 → 신도로 영입 → 노동/기도 중 배치(안 시키면 알아서 일 찾음)
- 충성도가 높을수록 산출이 좋아짐
- 크루세이드(액션 루프) 나가있는 동안 마을(관리 루프)은 자동으로 돌아감

핵심은 **"액션 나가있는 동안 홈베이스가 알아서 굴러간다"**는 감각 — 별도로 조작할 화면이 없어도 됨.

## 2. XOOX 설계안

### 2-1. 개념

전투 슬롯에 못 들어간 합류 펫은 자동으로 "무지개섬에서 지내는 중"이 된다. 매일(day tick) 소량의 골드/EXP를 벌어오고, 그 결과가 로그에 코멘터리 성격의 한 줄로 노출된다. **조작 UI 없이 텍스트만으로 1차 구현 가능.**

### 2-2. 데이터 (기존 컬럼 재사용 우선)

- 신규 CSV를 최소화한다: `party_member_config.csv`(기존)의 `member_id`만으로 대상 식별 가능 — 슬롯 밖 여부는 `getPartySlots()` 결과와 `joinedPartyMembers` 순서로 런타임 계산, 별도 저장 불필요
- 파견 결과 텍스트는 신규 소형 CSV 하나로:

```
island_task_config.csv
  task_id         PK
  liked_tag_hint  rescue_animal_config의 liked_tags 값과 매칭(예: FEED, WAIT, BOLD 등)
  flavor_text     "OO가 섬에서 낙엽을 모아왔다" 류 결과 문구 (%s = 펫 이름 치환)
  gold            산출 골드(소량)
  exp             산출 EXP(소량)
```

- **성격 재사용:** 구조 조우 태그매칭 퍼즐에 이미 있는 `rescue_animal_config.liked_tags`(예: 뭉치=GENTLE|WAIT)를 파견 결과 문구 선택에 그대로 재사용 — 새 "성격" 데이터를 안 만들어도 됨. WAIT 좋아하는 애는 "느긋하게 낮잠 자다 왔다" 계열, BOLD 좋아하는 애는 "여기저기 뛰어다니다 뭔가 물어왔다" 계열 등.

### 2-3. 흐름

1. day 진행 시 `joinedPartyMembers`에서 `getPartySlots()` 초과분(슬롯 밖 인원) 계산
2. 슬롯 밖 펫마다 `island_task_config`에서 `liked_tag_hint` 매칭되는 행 하나 랜덤 선택(없으면 폴백 문구)
3. 결과를 골드/EXP에 합산 + 로그에 한 줄 노출(코멘터리 톤, "— OO" 형식 재사용 가능)

### 2-4. 확장(2차, 지금 안 함)

- 별도 "섬" 화면에서 파견 상태 시각적으로 보기
- 파견 종류를 여러 개 중 선택(채집/휴식/정찰 등)하게 하기 — Cult of the Lamb의 "일 배정"에 해당, 지금은 자동 배정만

## 3. 개발 규모 (소~중)

- 신규 CSV 1개(`island_task_config.csv`, 소형)
- `engine.ts`에 day tick 로직 하나 추가(day_event_config 처리와 유사 패턴)
- 로그 카드 문구 1종 추가(기존 카드 렌더링 재사용)
- **화면 UI 없이 1차 구현 가능** — 텍스트 + 숫자만

---

## 4. 결정 필요한 것

1. 골드/EXP 산출량 — 전투로 버는 양 대비 얼마나 낮게 잡을지(밸런스 축, `03_BALANCE.md`와 연동 필요)
2. `island_task_config` 문구를 몇 종류나 준비할지
3. 슬롯 밖 펫이 하나도 없을 때(초반)는 이 시스템 자체가 안 보이는데, 그래도 되는지
4. PERMANENT(열두 등)와 RESIDENT 펫을 파견 대상에서 차별 둘지(예: PERMANENT는 항상 전투 우선 등)
