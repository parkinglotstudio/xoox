# 17. XOOX 전환 (카피바라 판타지 → XOOX Rainbow Island)

> 축: 이 프로젝트의 세계관·시나리오·핵심 메커닉을 XOOX 원본으로 바꾸는 작업의 SSoT
> 갱신: 2026-07-17
> **가져온 곳:** `plan_old\기획\XOOX_10_시나리오_구역01_개정.md`·`02_SYSTEM_정화규칙.md`·`06_DATA_수치색인.md` (RN/Expo 엔진은 폐기, **설계 아이디어만** 이관)
> **중요:** `plan_old`는 더 이상 참조하지 않는다. 이 문서가 그 안의 기획 내용을 이 프로젝트 기준으로 다시 정리한 것 — 앞으로는 이 문서가 SSoT.

---

## 0. 왜 이 문서가 따로 있는가

`02_CONTENT`·`03_BALANCE`·`04_SYSTEM`·`09_UI_UX`는 **지금 실제로 돌아가는 엔진**(캐릭터 1명, ATK/DEF/HP, 등급 롤+분기)을 설명하는 문서다. XOOX 전환은 이 엔진에 없는 개념(**펫 팀이 1→3마리로 늘어남**, **개체별 HP**, **정화 판정**)을 요구하므로, 기존 문서를 섣불리 고쳐 쓰면 "문서엔 있는데 엔진엔 없는" 거짓말이 생긴다. 그래서 **가져온 설계와 지금 엔진의 갭을 이 문서에서 먼저 명확히 하고**, 실제 구현이 끝난 항목만 하나씩 해당 축 문서(02/03/04/09)로 옮겨 확정한다.

## 1. 세계관 전환

| | 지금(카피바라 클론) | XOOX 원본 |
|---|---|---|
| 배경 | 범용 판타지(용병·해적·마법타워) | XOOX Rainbow Island — 학대·유기된 반려동물 구조 오디세이 |
| 주요 인물 | 없음(플레이어 단독) | Tigon(선장)·Piper(수호자)·Nashui(치유자)·Olmas(정화자) + 플레이어 |
| 적 정체 | 몬스터(메두사·골렘 등, 죽여서 격파) | **오염된 OOO** — 특정 빌런 없음, "오염"이 응축되는 것. 죽이지 않고 **정화**(corruption_gauge→0) |
| 톤 | 판타지 어드벤처 | "모두 가족이다, 버림받았어도 다쳤어도" — 구원 서사 |

**적용 원칙(확정)**: 새 적/이벤트는 전부 "오염된 OOO" 네이밍을 따른다. 사물처럼 보이는 적(예: 오염된 폐타이어더미)도 안에는 항상 구할 생명체가 있다는 전제를 유지한다.

## 2. 핵심 메커닉 갭 — 지금 엔진에 없는 것

| 개념 | XOOX 설계 | 지금 엔진 상태 | 필요한 작업 |
|---|---|---|---|
| **팀(파티)** | 1마리 시작 → Wave1·2에서 구조한 동료가 합류해 3마리까지 증가 → Day20 이후 고정 | **없음.** 캐릭터 1명 고정(`PlayerState.hp/atk/def`가 스칼라) | 파티 배열로 상태 구조 변경 필요(`PlayerState.team: Unit[]`) |
| **개체별 HP** | 유닛마다 자기 HP/maxHP, UI에 HP바 개수 = 팀 인원수 | **없음.** HP 하나만 표시 | 상단 스탯 UI를 유닛별 HP바 리스트로 교체 |
| **roster_scope** | 임시 동료(RESIDENT, 이 스테이지 한정) vs 영구 소장(PERMANENT, 파이널보스만) | **없음.** 지금은 스킬만 영구 학습, "동료" 개념 자체가 없음 | 신규 개념 — 어떤 데이터 허브에 둘지 결정 필요(아래 §4) |
| **정화 판정** | corruption_gauge를 0으로 만들면 승리(HP 깎아 죽이는 게 아님) | **없음.** 지금은 ATK로 상대 HP를 깎는 실승패 | 전투 판정 로직 자체를 바꿔야 함(§4.4 `simulateCombat` 영향) |
| **Memory Battle** | 파이널보스는 전투 대신 대화 선택 3라운드로 설득 | **없음** | 신규 전투 모드(스킬 루프 정지 + 선택지 UI) |

**결론: 이건 문서 몇 줄 수정이 아니라 실질적인 시스템 개발이 필요하다.** 다음에 이 부분을 어떻게 단계적으로 붙일지 논의 필요(§5).

## 3. 가져온 시나리오 — 구역01(하수도) 30일 개정판 (설계 원문)

> 원 출처: `plan_old\기획\XOOX_10_시나리오_구역01_개정.md`. 아래는 **설계 그대로**이며, 지금 엔진에 이식된 상태가 아니다(§2 갭 참조).

### 3.1 핵심 원칙
- 적 이름 = "오염된 OOO" (동물이든 사물이든, 벗겨보면 항상 구할 생명체)
- 빌런 없음 — 적은 "오염"이라는 현상이 점점 응축되는 것

### 3.2 Day 흐름 요약

| 구간 | 내용 |
|---|---|
| Day 1~7 | 정착(필러 이벤트) + 스킬 선택 #1 |

| Day 9~13 | 필러 + 스킬 선택 #2 |
| Day 14 | Wave2 — 오염된 길고양이 정화 → 하늘이 합류(3마리, 임시, **팀 완성**) |

## 4. 데이터 허브 반영 방향 (검토 필요, 아직 미확정)

지금 4허브(Entity/Item/Skill/Effect) 구조에 위 개념을 어떻게 끼워 넣을지 후보:

- **팀 유닛** → Entity 허브 확장(`entity_config`에 `is_party_member` 같은 플래그?) 또는 완전 신규 허브
- **roster_scope** → Item 허브(펫을 "아이템"처럼 다룸) 또는 신규 허브
- **오염된 OOO(적)** → 기존 `combat_enemy_config` 확장(이름 규칙만 바꾸면 되는 부분)
- **정화 판정** → `combat_tuning`에 새 키 추가 + `engine.ts`의 `simulateCombat` 분기 신설

### 6.1 설계 수정 (2026-07-17, 같은 날 재조정) — 개별 유닛 → 버프 캐리어

> 지시자 피드백: "3마리가 각자 전투력을 갖는 건 어려울 것 같다. 버프 형태로 주는 게 깔끔하다."

위 §6에서 처음 만든 "유닛별 개별 HP(TeamUnitState 배열)" 모델을 **그날 바로 폐기**하고 아래로 단순화했다:

- **전투 유닛은 모험가 1명만 유지**(`state.purifyHp`/`purifyMaxHp` 스칼라, 배열 아님)
- **합류 동료 = 버프 캐리어**: `party_member_config.purify_buff_pct`(뭉치+25%·하늘이+20%·열두+40%)를 `state.purifyBuffPct`에 즉시 누적 — Day 필러의 PURIFY_POWER 버프와 **같은 축**을 재사용(신규 계산식 없음)
- **비주얼**: HP바 대신 `renderPartyBuffBadges()` — 아이콘+이름+"정화력 +N%" 배지만 나열(`stage-team-bars` DOM 재사용, HP바 CSS는 안 씀)
- `PartyMemberDef.base_hp`·`TeamUnitState` 타입 삭제, `PlayerState.team` → `purifyHp/purifyMaxHp` + `joinedPartyMembers: string[]`로 교체

**재검증 완료**: Day8 Wave1 전투에서 "T1~T3 정화 -22.5 → 모험가 HP 75→70→65/80" 단일 HP 로그, "🐕 뭉치 / 정화력 +25%" 배지, "뭉치 합류! 정화력 +25% · 이번 여정 한정 동행" 메시지까지 실제 화면 확인.

**아직 안 한 것**: Day26 미니보스·Day30 파이널보스(Memory Battle)는 코드 경로는 준비됐으나(동일한 `resolvePurifyCombat`이 처리) 실제 클릭까지는 안 가봄. 밸런스(정화력 vs 타락 게이지 수치)는 XOOX_10 원안 그대로 이식한 것이라 **잠정** — 재튜닝 필요.
