# 38. 시나리오 작성 룰 — 걸음 기반 진행

> 작성: 2026-08-08 · 상태: 【**저작 규칙 SSoT**】
> 목적: 자동 진행(카피바라고식 간소화) + 공간 확장(Cozy Grove식 정화)을 한 게임에서 성립시키기 위한 **저작 규칙**을 고정한다.

## 0. 한 줄

> **하루 = 아일랜드에서의 한 걸음. 사건은 날짜가 아니라 노드에 붙는다.**

## 1. 상위 구조 【확정】

```
자동 진행 (기본)      버튼 1개 → 다음 노드로 알아서 간다 (모노폴리고식)
갈림길 (가끔)         버튼 2개 → "내일 어디로 / 무엇을" 2지선다
수동 탐방 (병행)      지금처럼 열어 둠 · 다른 이벤트용 · 별도 기획
```

- 갈림길은 **상시가 아니다.** 시나리오가 필요로 할 때만 배치한다.
- UI는 기존 `mainBtn`(원버튼) ↔ `choiceButtons`(2지선다) 전환을 그대로 쓴다. 새 화면 없음.

## 2. 규칙 1 — 하루 = 노드 하나 【확정】

> **버튼 한 번 = 한 지점 도착 = 하루 소비. 예외 없음.**

하루가 노드 하나여야 진행이 **셀 수 있는 칸**이 된다. 하루에 두 사건이 일어나거나 한 노드가 이틀을 먹는 순간, 시나리오를 칸 단위로 저작할 수 없게 된다.

### 따라오는 수량 규칙

갈림길이 있으면 **배치 노드 > 밟는 노드**여야 한다. 안 밟는 칸이 곧 「가지 않은 길」이다.

| 구역 구성 | 밟는 칸 | 배치할 노드 |
|---|---|---|
| 갈림길 없음 | N | N |
| 갈림길 1개 (2갈래 × 3칸) | N | N + 3 |
| 갈림길 2개 | N | N + 6 |

### 현황 (2026-08-08 실측)

| | 값 |
|---|---|
| 배치된 노드 | **50개** (구역별 13 / 12 / 13 / 12) |
| `30_월드맵_구조.md` 기재 | 41개 → **낡음, 정정 필요** |

갈림길과 체인(§4)을 넣으려면 구역당 **18~21개**, 전체 **72~84개**가 필요하다. 현재 50개이므로 **20~30개 추가 저작**이 남았다.

## 3. 규칙 2 — 사건은 날짜가 아니라 노드에 붙는다 【확정】

> `day 30 = 보스` **(폐기)** → `s2_boss 노드 도착 = 보스` **(채택)**

「시나리오와 딱딱 맞는다」의 기술적 정의가 이것이다. 날짜에 붙이면 플레이어가 지금 **어디에 있는지 모르는 채로** 사건이 발동한다. 갈림길에서 왼쪽에 가 있는데 오른쪽 사건이 날짜 때문에 터지는 사고가 구조적으로 발생한다.

### 일수 상한 — 【정정 2026-08-08】 60일로 되돌림

초판에서 「상한 불필요」로 적었으나 **뒤집혔다.**

| 시점 | 판정 | 근거 |
|---|---|---|
| 초판 | 상한 없음 | 마지막 노드를 밟으면 끝나므로 총 일수를 셀 필요 없음 |
| **현행** | **60일 고정** | 지시자 확정: **「배가 60일 있다가 온다」** — 픽션이 상한을 되살렸다 |

단, **진행 메커니즘은 그대로 노드 기반**이다. 날짜가 구역을 밀지 않고, 60일은 **판의 제한 시간**으로만 작동한다. 자세한 것은 [`39`](./39_게임시스템_확정.md) §2.

### 해결해야 할 모순 【현존】

| 파일 | 기준 | 판정 |
|---|---|---|
| `area_connection_config.csv` | `unlock_condition = NODE:s1_gate` — **노드 기반** | ✅ 규칙 2와 일치 |
| `stage_map_config.csv` | `day_start` / `day_end` — **날짜 기반** | ❌ 규칙 2 위반 |

관문 노드를 안 밟았는데 날짜가 되면 다음 구역으로 끌려가고, 관문을 일찍 밟아도 날짜가 안 되면 못 넘어간다.

### 이관 대상

| 파일 | 처분 |
|---|---|
| `combat_day_schedule.csv` (day 8·15·23·30·38·45·52·60) | **삭제** — `area_npc_config`의 COMBAT/MINIBOSS/BOSS 노드가 같은 사건을 이미 정의한다. 중복 테이블 |
| `day_event_config.csv` (day 12·26·40·54·57) | **노드로 이관** — 서사 비트 4 + TEAM_LOCK 1. 현재 시나리오의 전부 |
| `stage_map_config.csv` `day_start`/`day_end` | **제거** — 구역 배정은 노드 해금으로 일원화. 배율·`party_slots`는 `map_order`에 유지 |
| `combat_tuning`: `final_challenge_min_day=55`, `edge_near_end_days=2` | **노드 조건으로 치환** |
| `rollIsCombat()` 확률 롤 (`main.ts`) | **제거** — 전투는 노드에만 존재 |

## 4. 규칙 3 — 사건은 체인으로 쓴다 【확정】

> **정화 = 운반이다.** 촉매를 「줍는」 게 아니라 **원인에게서 빼앗아 온다.**
> 지시자 확정: 「정화를 내가 운반이라고 하는 거야」

### 4-1. 표준 체인 (5걸음)

| 걸음 | 단계 | 하는 일 |
|---|---|---|
| 1 | **발단** | 오염 발견 — 아직 못 고침 |
| 2 | **조사** | 주변을 찾아본다 → 단서 **2개를 동시에** 연다 |
| 3 | **분기** | 곰의 소행 / 호랑이의 소행 — **갈림길** |
| 4 | **해결** | 고른 쪽으로 가서 전투 → 아이템 획득 |
| 5 | **귀환** | 그 지역으로 **되돌아가** 적용 = 정화 |

> **조사 노드 하나가 단서 둘을 동시에 여는 것**이 핵심이다.
> 그래야 3걸음째 갈림길이 억지로 끼워넣은 것이 아니라 **조사의 결과**로 나온다.

### 4-2. 전투의 위치 — 【정정】

초판에서 「전투는 시나리오를 잇지 못한다」고 적었으나 **정정한다.**

전투가 이야기를 못 잇는 게 아니라 **앞뒤가 없는 전투**가 못 잇는다. 체인 4걸음째에 놓인 전투는 「왜 싸우는지」(3걸음째 분기)와 「싸워서 뭘 얻는지」(5걸음째 열쇠)를 양쪽에 달고 있어 완전히 다른 물건이 된다.

**단독 노드로서의 전투는 구두점(구역의 마침표)으로만 쓴다.** 현재 전투는 3중으로 발동 중이며, 규칙 2로 2·3이 제거되면 **50노드 중 8개(16%)**로 내려간다.

1. `area_npc_config`의 COMBAT 노드 8개 ← 유지
2. `combat_day_schedule.csv` 날짜 강제 8회 ← 삭제
3. `rollIsCombat()` 확률 롤 ← 삭제

### 4-3. 데이터 갭 【미해결】

현재 체인을 표현할 수 없다.

| 필요한 것 | 현재 |
|---|---|
| 노드 A 클리어 → 노드 B 공개 | ❌ `appear_condition` **50/50 전부 ALWAYS** |
| 오염마다 다른 열쇠 | ❌ `needs_catalyst_id` 전부 `cat_clean_water` — **열쇠 1개에 자물쇠 5개** |
| 전투 전리품이 촉매가 됨 | ❌ 전투 보상과 촉매가 분리되어 있음 |

## 5. 규칙 4 — 되돌아가는 것도 하루다 【확정】

> 귀환 걸음도 규칙 1의 예외가 아니다. **하루를 쓴다.**

이로써 **거리가 의미를 갖는다.** 「저기까지 갔다 오면 3일인데, 할까?」라는 저울질이 생기고, 갈림길에서 「곰이 더 가깝다」가 선택 이유가 될 수 있다.

### 검증 결과 — 이동 구조는 이미 있다 【2026-08-08 실측】

| 항목 | 상태 |
|---|---|
| 자유 2D 이동 (`walkTo`) | ✅ y를 올리든 내리든 가능. 단방향 제약 **없음** |
| 구역 왕복 | ✅ `exitsOf` — *"앞으로 나갈 때만 잠그고, 되돌아가는 방향은 항상 열어 둔다"* |
| 클리어 노드 표시 / 소진 노드 숨김 | ✅ |
| 정화 후 맵 톤 갱신 | ✅ `refreshCurrentArea` · `applyPurifyLook` |

> ⚠️ `explore.ts` 상단 주석의 *"아래에서 시작해 위로 향한다"* 는 **의도 서술이지 코드 제약이 아니다.** 단방향으로 오독하지 말 것.

### 남은 배선

1. **자동 진행이 이 이동을 안 쓴다** — `walkTo`는 수동 탭에서만 호출. 버튼은 여전히 확률을 굴린다
2. **걸어도 하루가 안 간다** — `walkTo`는 애니메이션일 뿐. `state.day += 1`은 `onMainBtnClick`에서만 발생

## 6. 규칙 5 — 노드는 항상 존재, 정체만 조건부 공개 【확정】

> 노드를 **숨기지 않는다.** 대신 **정체를 잠근다.**

```
오염 보기 전   회색 「?」        — 뭔가 있다는 것만 안다
오염 본 후     「곰 발톱 자국」   — 정체가 밝혀지고 조사 가능
```

### 왜 이 형태인가

| 방식 | 판정 |
|---|---|
| 처음부터 정체까지 다 보임 | ❌ **자동 진행에선 장점이 발동하지 않는다.** 「순서를 안 지켜도 안전」은 플레이어가 순서를 정할 때만 의미가 있는데, 자동 진행은 시스템이 다음 걸음을 정한다. 값은 치르고 얻는 게 없음 |
| 조건 만족 시 노드가 생성됨 | ⚠️ 이야기 강제력은 좋으나 노드가 튀어나와 어색 |
| **노드 상시 · 정체 조건부** | ✅ **채택.** 튀어나오지 않으면서 의미는 순서를 따라 열린다 |

### 부수 효과 — 「의미 없는 노드」 문제 해소

현재 50개가 전부 `ALWAYS`라 처음부터 다 떠 있다. 자동 진행으로 스쳐 지나가면 플레이어는 「뭔가 많네」 하고 **전부 흘린다.** 정체를 잠그면 지도에 뜬 것 중 **지금 의미 있는 것만** 읽힌다.

### 데이터 영향

`area_npc_config.csv`에 공개 조건과 미공개 표기가 필요하다. (컬럼 설계는 구현 시 확정)

## 7. 규칙 6 — 노드 해결 동사 【논의 중】

**자기완결형**(그 자리에서 끝)과 **연결형**(다른 노드와 이어짐)으로 갈린다. 시나리오가 「딱딱 맞는」 느낌은 **연결형에서만** 나온다.

### 자기완결형

| 동사 | 막는 것 | 현재 |
|---|---|---|
| **이긴다** (전투) | 적 HP | ✅ COMBAT 4 · MINIBOSS 2 · BOSS 2 |
| **고른다** (분기) | 대가 | ✅ `branch_config` 11종 |
| **줍는다** (발견) | 없음 — 밟으면 획득 | ✅ MEMORY 8 · CATALYST 4 |
| **논다** (미니게임) | 손기술 | ✅ MINIGAME 4 |

### 연결형

| 동사 | 막는 것 | 현재 |
|---|---|---|
| **적용한다** (정화=운반) | 앞 노드에서 얻은 물건 | ✅ `tryApplyPurify` · BLIGHT 5 — 단 **1:1 고정** |
| **다가간다** (구조) | 아이의 경계심 | ✅ `buildRescueOptions` (5턴 태그 매칭) |
| **전달한다** (운반) | A노드에서 받은 물건을 B노드로 | ❌ 없음 |
| **데려간다** (동행) | 특정 아이가 파티에 있어야 열림 | ❌ 없음 |
| **다시 온다** (재방문) | 상태 변화 후 같은 노드 재방문 | ❌ 없음 |

### 미결

- 연결형 미구현 3종 중 무엇을 먼저 넣을지
- 갈림길이 저울질하는 축 (누구를 구할까 / 어떻게 갈까 / 단순 변주)

---

## 8. 규칙 7 — 2지선다 층위 분리 【미결 · 선행 조건】

현재 2지선다가 이미 두 종류다.

| 층위 | 위치 | 의미 |
|---|---|---|
| 사건 선택 | `branch_config` 11종 | 이 사건에 참여할까 |
| 구조 접근 | `buildRescueOptions` | 어떻게 다가갈까 |
| **경로 갈림길** | ❌ 없음 — 신규 | **어디로 갈까** |

경로 갈림길을 추가하면 **세 종류가 같은 모양의 버튼 두 개**로 표시된다. 되돌릴 수 없는 경로 결정이 단순 보상 선택과 구분되지 않는다.

> **갈림길을 배치하기 전에 층위별 시각 언어를 정해야 한다.** 배치 후에는 이미 쌓여 있어 수정 불가.
