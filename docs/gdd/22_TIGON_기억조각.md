## 0. 왜 필요한가 (빈 자리 확인)

`19_XOOX_현행_정합.md`에 이미 이렇게 적혀 있다:

> Tigon — 선장(개+고양이 믹스, 섬을 이끔). **섬을 떠나면 힘·기억 상실** → 최종 회복 대상

그런데 이 설정을 플레이어에게 **어떻게 전달할지는 아직 없다.** 지금 Tigon은 인트로 컷신 대사 한 줄("너는 남아서 섬을 지켜. 여기 기다리는 아이들이 있잖아.") 이후로는 등장하지 않는다. 서사상 제일 무거운 캐릭터인데 전달 수단이 없는 상태 — 이 문서가 그 수단을 제안한다.

## 1. 벤치마크 — Stray의 B-12 기억 조각

- 27개의 짧은 기억 조각이 게임 전역에 흩어져 있고, 특정 오브젝트를 스캔하면 하나씩 언락
- 기억은 플레이어(고양이)가 아니라 **동반자 드론 B-12의 것**
- 조각을 다 모으면 "B-12가 사실 인간이었다"는 진실이 드러남 — 미스터리 박스 구조
- 핵심은 **조금씩, 탐색/진행에 자연스럽게 얹어서, 마지막에 진실 공개**라는 페이싱

---

## 2. XOOX 설계안

### 2-1. 개념

플레이어가 60일 동안 진행하며 **Tigon의 잃어버린 기억 조각**을 하나씩 얻는다. 조각은 짧은 시나리오 로그 1~2줄 + 그걸 본 다른 리더의 코멘터리 반응으로 구성된다. 60일차(파이널보스)에서 조각이 전부 모이면, **이미 계획돼 있던 "Memory Battle"**(대화 선택으로 정화하는 파이널보스, `19` 문서 §2에 [예정]으로 명시)이 곧 "Tigon의 잃어버린 기억을 되찾는 결전"이 된다 — 이름부터 의미가 맞아떨어지므로 별도 이름을 새로 안 만들고 이 축에 합류시킨다.

### 2-2. 데이터 (신규 CSV 1개)

```
tigon_memory_config.csv
  memory_id       PK
  order           표시 순서(1~N)
  unlock_trigger  예: DAY(특정 day) / STAGE_CLEAR(스테이지 클리어) / RESCUE_COUNT(구조 누적 N회)
  unlock_value    트리거 값(day 번호, 스테이지 id, 누적 횟수 등)
  scenario_text   기억 조각 본문(시나리오 로그 1~2줄)
  reactor         이 조각을 보고 코멘터리로 반응할 캐릭터(Piper/Nashui/Olmas 중 1)
  reaction_text   그 캐릭터의 짧은 반응 대사
```

### 2-3. 흐름

1. `unlock_trigger` 조건 충족 시 시나리오 로그 카드로 조각 노출 (기존 카드 렌더링 재사용, 새 UI 불필요)
2. 곧바로 `commentary_config.csv`에 새 트리거 `MEMORY_UNLOCK` 한 종 추가해 반응 노출 (기존 코멘터리 시스템 재사용)
3. 마지막 조각(order 최대값)은 60일차 Memory Battle 진입 직전에 강제 언락 — 파이널보스 진입 컷신과 자연 연결

### 2-4. 분량 제안 (잠정)

Stray의 27개는 XOOX의 60일 스케일엔 과함. **스테이지(15일)당 2~3개 × 4스테이지 = 8~12개** 정도로 잠정 제안 — 실제 숫자·트리거 지점·대사 내용은 확정 필요.

## 3. 개발 규모 (가벼움)

- 신규 CSV 1개(`tigon_memory_config.csv`)
- `commentary_config.csv`에 트리거 1종 추가
- `engine.ts`에 언락 조건 체크 함수 1개(day_event_config 처리 로직과 같은 패턴 재사용 가능)
- 새 UI 화면 불필요 — 기존 로그 카드 + 코멘터리 컴포넌트 재사용

---

## 4. 결정 필요한 것

1. 언락 트리거를 day 고정으로 할지, 스테이지 클리어 기준으로 할지, 구조 누적 횟수 기준으로 할지
2. 정확한 조각 개수와 각 조각의 실제 대사(현재는 자리만 잡음)
3. 조각을 모아보는 별도 열람 화면(도감 같은)을 만들지, 로그에 흘러가면 끝인지
4. Memory Battle(60일 파이널보스) 자체가 아직 미구현이므로, 이 문서 단독으로도 진행 가능하지만 최종 완결은 Memory Battle 구현과 함께여야 함
