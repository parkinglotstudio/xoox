## 0. 한 줄

**버림받은 방랑자가 무지개섬(집)에서 배를 타고 신비의 섬으로 나가, 60일 안에 오염된 생명·장소를 정화하고 아이들을 구해, 살아서 배를 타는 구조 오디세이.**

원형은 모바일 **카피바라 고**의 「하루 버튼 + 하단 로그」다. 지금은 그 뼈대 위에 **XOOX Rainbow Island** 세계관·노드 동선·3D 탐방·정화를 얹은 상태다. 카피바라 클론이 목표가 아니다.

핵심 메시지: **「모두 가족이다 — 버림받았어도, 다쳤어도, 타락했어도.」**  
톤: 코믹·귀엽고 밝게. 공포·잔혹 배제. 적은 빌런이 아니라 **오염**.

## 1. 세계 · 인물

투명 반구형 우주선 **XOOX (Rainbow) Island** — “눈물이 무지개가 되는 곳.” 학대·유기된 반려동물의 안식처.

| 인물 | 역할 |
|---|---|
| **방랑자** | 플레이어. 다리가 불편한 버림받은 반려동물. 여정의 손 |
| **Tigon** | 선장(개+고양이). 섬을 이끎. 떠나면 힘·기억 상실 → 결말 회복 대상 |
| **Piper** | 수호자(셰퍼드). 직관·보호. 전투·위험 코멘터리 |
| **Nashui** | 치유자(고양이). 새침·코믹. 분기·유혹 톤 |
| **Olmas** | 정화자. 신호 감지. 발견·정화 |

시그니처 펫: **뭉치**(스테이지1 구조) · **하늘이**(스테이지2) · **열두**(최종, 영구). 정화 완료 비주얼은 흑바탕 사이버펫(3NOFILTER·Flux·Lumos·해커캣·Gizmo).

용어 네 축: **Purify(정화) / Empathy(공감) / Heal(치유) / Courage(용기).**  
인간 판타지 어휘(검·오크·메두사) 금지. 액션 전투 상대는 **인간이 남긴 오염·산업 잔재**. 구조 대상(강아지·고양이)과 형태를 섞지 않는다.

## 2. 두 섬 · 한 판 루프 【시스템 SSoT = GDD 39】

| 섬 | 이름 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| **집** | 무지개섬 = **로비** | 기록·도감·파견·성장·외출 준비 | 위험·상실 |
| **모험지** | 신비의 섬 = **여정** | 구조·정화·탐방·전투 | 느긋한 정리·영구 성장 |

```
무지개섬 ──배──▶ 신비의 섬 ── 60일 ──▶ 배가 온다 ──▶ 무지개섬
                         │
                         └─ 쓰러짐 ──▶ 그 판에서 구한 아이 전부 상실
```

- 한 판 = **60일**. 배가 60일 뒤에 온다. **중간 귀환 불가.**
- 하루 = **노드 하나**. 섹터 이동도 하루. 사건은 날짜가 아니라 **노드**에 붙는다. (GDD 38)
- 능력 2층: 섬에서 줍는 **정기(일시, 귀환 시 소멸)** / 로비에서 키우는 **기본 능력(영구)**. 기본 능력의 구체 목록은 미정.
- 아이 3층: **전투 슬롯**(구역마다 2→5) · **펫 슬롯 2**(능력 부여) · 나머지 **정찰**(섬 안에서 자원).

로비 화면은 구현되어 있다. 단말기(스크랩·도감·일지·지도), 파견, 모험(자동), 파티, **배=외출**.  
GDD 33의 「여정 중 언제든 로비」는 **39가 폐기**. 로비는 **판이 끝난 뒤 / 아직 안 나간 집**.

## 3. 네 기둥 (필러 컨셉)

이름은 지시자 확정. **로비에 버튼 4개로 쪼개지 않는다.** 탐구·정화는 여정 안에서 일어난다.

| 기둥 | 의미 | 어디서 | 현행 시스템 |
|---|---|---|---|
| **파견** | 섬에 남은 아이들이 가족을 지킨다 | 로비 | 슬롯 밖 자동노동 (`island_task_config`) → 정찰로 개편 중 |
| **탐구** | 발품으로 촉매·흔적·기억을 찾는다 | 여정 맵 | 탑뷰/3D 탐방 · MEMORY · MEMO · LOCATION · CATALYST |
| **도전** | 오염·잔재를 돌파한다 | 여정 메인 | 노드 밟기 · 액션 전투 · 관문 · 미니게임 · 등급 게이지 |
| **정화** | 촉매를 적용해 생명·장소를 되돌린다 | 여정 | 줍기→적용 · AREA 색 회복 · LIFE 구조 · 3D 파도+레이저 |

정화 루프 (GDD 36): **가다 → 찾다 → 쓰다 → 되살다.**  
대상 두 종류: **AREA**(장소, Cozy식 원형 색) · **LIFE**(생명, 구조/합류). 같은 “적용” 동사.

가장 중요한 규칙 (GDD 44 R3): **정화가 되어야 그 지역에 뭐가 있는지 안다.**  
정화 전 = 어둡다. 정화 미션 도중에 등급 행운이 터진다. 정화가 끝나야 탐방·스킬·조우·전투가 열린다.

## 4. 신비의 섬 지도

섬 ≈ **1 km**. **3×3 격자**, 칸 ≈ **333 m**. 플레이어가 걷는 건 **육지 십자 5칸**. 코너 4칸은 바다(아트만, 보행 금지).

```
 i00 바다   │ i01 북부     │ i02 바다
 i10 서부   │ i11 중앙     │ i12 동부
 i20 바다   │ i21 부두     │ i22 바다     ← 스폰 = 부두
```

| 섹터 | 역할 |
|---|---|
| i21 부두 | 도착 · 첫 정화 · 첫 구조 · 관문 `s1_gate` |
| i11 중앙 | 갈래가 갈리는 허브 · 전망대 |
| i12 동부 | 유혹 · 감시 · 구역 보스 |
| i10 서부 | 재방문 · 폐기물 거인 |
| i01 북부 | 기억 수렴 · 최종 보스 `s4_final` |

동부↔서부는 중앙을 거친다(2칸=2일).  
완주(동+서) = **정확히 60일, 여유 0**. 갈래를 포기하면 시간은 남지만 아이가 적고 섬이 어둡다. 최종전 난이도가 게이트.

섬 정화도 = 정화한 AREA 오염 / 5곳.

스케일·에디터: GDD 42. 육지 배경 아트: GDD 44(섹터배경). 탐방 안개(시야≈10m, 미탐방 노드 숨김): GDD 45.

## 5. 하루가 굴러가는 방식 (섹터 사이클)

옛 방식은 「다음날」이 주사위 3개(전투? 구조? 콘텐츠?)를 굴렸다. **지금은 노드를 밟는다.** 동선이 시나리오다. (GDD 43→44)

SSoT: `data/sector_beat_config.csv`. **비트 순서는 고정, 안은 랜덤.**

| 비트 | 이름 | 노드 |
|---|---|---|
| B1 | 오염 발견 | `BLIGHT` |
| B2a | 촉매 찾기 | `CATALYST` (B2b와 **합치면 안 됨**) |
| B2b | 미션 도중 | `DAILY` `TRACE` `FILTER` |
| B3 | 정화 완료 | `BLIGHT_APPLY` (B1과 같은 자리) |
| B4 | 지역 탐방 | `MEMORY` `LOCATION` `REST` `MEMO` `NPC` `DAILY` |
| B5 | 스킬 | `SKILL` |
| B6 | 조우 | `RESCUE` |
| B7 | 전투 | `COMBAT` |
| B8 | 다음 지역 · 길 판정 | `MINIBOSS` `BOSS` |

길 판정 (`path_judgment_config.csv`): 등급이 이동 모드.

| 등급 | 이동 |
|---|---|
| 대박 | `FORK_GOOD` 갈림길 |
| 중박 | `FORK_COSTLY` 갈림길 (대가) |
| 보너스 | `RANDOM_SAFE` 자동 |
| 운빨망함 | `RANDOM_BAD` 자동 |

랜덤 3층: (L1) 비트 안 어느 노드 (L2) 몇 번 (L3) 길 판정.

구조(`RESCUE`)는 지도에 자리 있는 노드. 5턴 2지선다 태그 매칭. 정화도 0→goal. 실패=아이 상실이므로 GOOD 불가 턴이 있어도 NEUTRAL로 버틸 수 있게 수치를 맞춰 둠.

## 7. 화면 구성 (지금 실제로 보이는 것)

앱 씬 (`src/scene.ts`): `boot` → `intro` → `cutscene` → **`lobby`** → **`journey`**. 한 번에 하나만.

프레임: 가로 폰 셸, 최대 약 **1000×480**, 16:9.

### 7-1. 로비 (무지개섬)

- 배경 레이어 분리: `lobby_hub_before.png` / `after`. 배 = 외출. 캐릭 idle.
- 하단 탭: 배(홈) · 외출 · 파견 · 파티 · 기록(단말기).
- 단말기 앱: 스크랩(Tigon 기억) · 도감(사연) · 일지 · 지도(색 회복).
- 레이아웃 SSoT: `data/ui/layout/lobby_layout.json` · 편집 `npm run dev:layout`.
- 색·톤 SSoT: `docs/art/11_XOOX_CYBERPET_PALETTE.md`. GDD 37 오두막·무지개는 **초판, 색의 정본 아님**.

### 7-2. 여정 (신비의 섬)

상하 2단 + 오버레이 (GDD 26, 셸 이식됨).

```
상단: 브랜드 · 지역칩 · 타임라인 · HP/젬
본문: 3D 무대(탐방) + 왼쪽 파티 HUD + 가운데 활동 토스트 + 오른쪽 필러(구조 로그)
하단: 버튼 레일만 (좌·우에 대박/중박 게이지) · 「다음날」=다음 노드
```

PNG 셸/금색 버튼 9-slice **미사용**.  
탐방: 좌하단 십자 패드. 무대 탭=걷기(하루 안 씀) · 노드 접근=하루 · 섹터 이동=하루.

### 7-3. 여정 3D가 한 화면에 겹치는 레이어 (GDD 46)

플레이어가 “먼 산”으로 보는 것은 **스카이박스가 아니다.**

```
카메라 (등 뒤, 거의 수평, FOV 72)
  캐릭 · 근경 프롭
  바닥 타일/스플랫          ← 밟는 땅
  탐방 안개 (근거리)         ← GDD 45
  거리 안개 (3D fog)
  ★ 지평선 원통 한 장        ← 산+대기+구름. 실제로 보이는 원경
  스카이박스                 ← FOV 72에서 거의 안 보임
```

정화전 원경 확정(v16). 정화후는 **같은 산 구도, 하늘만 열림**.  
정화 연출: 바닥과 원경이 **같은 파도 마스크**로 열리고, 경계에 시안 레이저. 타일 아트 자체는 아직 정화후 전용으로 안 그림 → 멀리 **정화 안 된 칸**이 보이는 것은 의도된 구역 단위(한 섹터만 정화)일 수 있다.

수치: `data/ui/layout/journey3d_layout.json`. 놀이터: `npm run dev:fpv`.

### 7-4. 전투

옛 카피바라식 **상단 턴 로그 액션 전투**는 엔진에 남아 있다 (`simulateCombat`, ACTION 적).  
XOOX 본편 방향의 3D 전투는 **자동 정화 습격** (거점 지키기, AutoPilot, 정화 총, 웨이브). 턴제 VS 화면으로 되돌리지 않는다.  
툴: `npm run dev:raid`. 본편 여정과의 연동은 진행 중.

구조 조우는 전투가 아니라 **태그 매칭 퍼즐**.  
60일 최종은 기획상 **Memory Battle**(대화 선택 정화) — 개발 예정.

## 9. 지금 이렇게 쓴다 (플레이 · 개발)

1. `npm run dev` → localhost:5173  
2. 인트로/컷신 → **로비**

## 11. 작업 규칙 (에이전트)

- 새 기능·구조화 전에 **분류를 밝힌다** (Spike / Bounded / Architectural) → 짧은 설계 → **지시자 승인 후** 코드.
- 버그 = 추측 수정 금지. 재현·원인부터.
- 3D 전투는 자동 정화 연출. 턴제 VS 복구 금지.
- 외부 게임 소스는 베끼지 않는다. 응용만, 소스 받기 전 시작 금지.
- 지시자는 프로그래머가 아님. 애매하면 먼저 묻는다.
- UI를 바꿨으면 로컬에서 화면을 보고 의도를 확인한다.

시작했으면: `npm run dev`로 로비→외출까지 띄운 뒤, **이번 세션이 이어서인지 / 어느 축인지** 한 줄로 물어본다.
