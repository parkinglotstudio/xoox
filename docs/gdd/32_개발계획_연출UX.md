## 0. 방법 (단서 방식)

1. **연출·UX가 제품의 주연.** 시스템 배선은 UX 비트를 받치기 위해만 손댄다.  
2. **이미 있는 플로우를 먼저 예쁘게.** 새 시스템·새 레퍼런스 확장보다, 플레이 중인 순간의 완성도.  
3. **한 Phase = 한 체감.** 끝나면 플레이만으로 “뭔가 좋아짐”이 보여야 한다.  
4. **문서 드리프트를 같이 닫는다.** 코드가 진실이면 문서를 고친다.  
5. **큰 작업 전 백업 폴더.** 커밋은 지시자 승인 후에만.  
6. **검증:** `25` §9-1 — 애니 finish 후 측정, `#feed` 내부 제외, 최종 렌더(글자)로 판정, 절대경로.

## 2. 로드맵

```
Phase 0  문서 정합 + 31/32 고정          ← 이번 착수와 동시
Phase 1  전투·복귀·패널 퇴장 UX          ← 체감 최우선
Phase 2  탐방 발견감(MEMORY) + 노드 복귀감
Phase 3  정화 전투 스킨 (`18`)
Phase 4  스크랩북·빈상태 폴리시
Phase 5  가로 패널 폴리시 · 실기기
Phase 6  폰 UI(단말기) — 별도 착수 승인
```

아트(배경·이동 스프라이트)는 **전 Phase와 병렬 가능**하나, UX Phase를 블록하지 않는다(플레이스홀더 유지).
