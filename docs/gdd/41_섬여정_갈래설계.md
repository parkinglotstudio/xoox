# 41. 섬 여정 갈래 설계 — 60일 예산 · 정화도 · 구조 밸런스

> 작성: 2026-08-08 · 상태: 【**여정 구조 SSoT**】
> 목적: 3×3 섬에서 **하나의 목표로 가는데 갈래에 따라 달라지는 60일**을 성립시킨다.
> 관련: [`40`](./40_인게임_비주얼_작업정리.md) 3×3 십자 · [`39`](./39_게임시스템_확정.md) 60일 한 판 · [`38`](./38_시나리오_작성룰.md) 저작 룰 · [`36`](./36_정화_촉매_지역정화.md) 정화
> 지시자 방향: 「수십 갈래를 사람이 외울 수 없다 — 툴이 들고 있어라」 · 「섹터 이동도 하루」 · 「가혹하게」

## 0. 한 줄

> **부두에 내려 60일. 갈래를 다 돌면 정확히 60일 — 여유 0.**
> 갈래를 포기하면 시간은 남지만 아이가 적고 섬은 어둡게 남는다.

## 1. 결정 사항 (지시자 위임 · 2026-08-08)

지시자가 「이제 네가 결정도 해라」고 위임한 항목의 판단과 근거.

| # | 결정 | 근거 |
|---|---|---|
| 1 | **섹터 이동 = 하루** | 지시자 확정. 십자 구조라 중앙을 계속 되돌아가므로 거리가 실제 비용이 된다 |
| 2 | **북부(최종)에 클리어 조건을 걸지 않는다** | OR 조건(`동부 or 서부`)은 현 `unlock_condition` 형식으로 표현 불가. 대신 **최종 보스의 난이도가 게이트** — 아이를 안 구하면 전투력이 모자라 못 이긴다. 코드 변경 없이 같은 긴장을 만든다 |
| 3 | **부두 관문(`s1_gate`)만 하드 잠금** | 최소한의 「하나씩 열린다」. 부두를 다 훑지 않고 중앙으로 새는 것을 막는다 |
| 4 | **중앙 i11에 노드 4개 추가** | 허브가 통행세만 받는 방이면 안 된다. 4개를 넣으면 완주가 **정확히 60일**이 된다 |
| 5 | **구조 정화도 목표를 구역별 커브로** | 20마리 전부 `goal=100`이라 커브가 없었다. §5 |
| 6 | **섬 전체 정화도 = AREA 오염 5곳 기준** | LIFE 정화는 별도 집계(구조). 맵에서 보이는 색 회복과 1:1 |

## 2. 섬 구조 (40 §3-1 기준)

```
 i00 바다  │ i01 북부  │ i02 바다        코너 4칸 = 아트만 (보행 금지)
 i10 서부  │ i11 중앙  │ i12 동부        육지 십자 5칸만 보행
 i20 바다  │ i21 부두  │ i22 바다        부두 = 외출 스폰
```

| 섹터 | 노드 | AREA 오염 | 역할 |
|---|---:|---:|---|
| i21 부두 | 13 | 1 | 도착 · 첫 정화 · 첫 구조 · **관문 `s1_gate`** |
| i11 중앙 | **4** | 1 | **갈래가 갈리는 자리** · 전망대에서 섬 정화도 확인 |
| i12 동부 | 12 | 1 | 유혹 · 감시 · 구역 보스 |
| i10 서부 | 13 | 1 | 재방문 · 폐기물 거인 |
| i01 북부 | 12 | 1 | 기억 수렴 · **최종 보스 `s4_final`** |
| **합계** | **54** | **5** | |

모든 이동이 중앙을 거친다. 동부↔서부는 2칸(= 2일).

## 3. 루트와 60일 예산 【확정】

일수 = 노드 수 + 섹터 이동 수. 이동 = 1(부두→중앙) + 2×선택섹터 + 1(중앙→북부).

| 루트 | 일수 | 이동 | 섬 정화도 | 여유 |
|---|---:|---:|---:|---:|
| 최단 — 갈래 생략 | **31일** | 2 | 60% | 29일 |
| 동부만 | **45일** | 4 | 80% | 15일 |
| 서부만 | **46일** | 4 | 80% | 14일 |
| 동부 → 서부 | **60일** | 6 | **100%** | **0일** |
| 서부 → 동부 | **60일** | 6 | **100%** | **0일** |

### 3-1. 왜 이 숫자가 좋은가

- **완주 = 정확히 예산.** 한 걸음도 낭비할 수 없다. 「가혹하게」가 숫자로 실현된다
- **포기하면 시간이 남는다.** 대신 아이가 적고(전투력↓) 섬이 어둡다(정화 보상↓) → 최종전에서 갚는다
- **저울질이 저절로 생긴다.** 게이트를 걸지 않아도 「다 구할까 / 안전하게 갈까」가 성립한다 (§1-2)

> 툴에서 루트별로 60일 전체를 하루씩 읽을 수 있다 — `npm run dev:scn` → ④-2 여정 갈래 → 「읽기」.

## 4. 섬 전체 정화도 【신규 시스템】

### 4-1. 정의

```
섬 정화도(%) = 정화한 AREA 오염 수 / 섬 전체 AREA 오염 수 (5)
```

- AREA 오염 5곳: 부두 · 중앙 · 동부 · 서부 · 북부 각 1곳
- LIFE 정화(반려동물)는 **여기 안 넣는다** — 구조 기둥으로 따로 집계
- 맵 비주얼은 이미 `purifyFoci[]` + `reveal_radius_pct`로 원형 확산 구현됨 (`40` §5-3)

### 4-2. 구간 효과 【확정 · 그 판 안에서만 유효】

`39` §3에 따라 정화도 효과도 **귀환하면 소멸**한다. 영구 성장은 기본 능력뿐.

| 정화도 | 이름 | 효과 |
|---:|---|---|
| 25% | 섬이 숨을 쉰다 | 정화한 지역의 촉매 노드가 1회 재생 |
| 50% | 색이 반쯤 돌아온다 | 정찰조 산출 증가 |
| 75% | 아이들이 경계를 풀다 | 구조 조우 성공 판정 완화 |
| 100% | 섬이 완전히 깨어난다 | 최종 보스 타락 게이지 감소 |

75%가 구조를 쉽게 만들고, 100%가 최종전을 쉽게 만든다 — **정화가 곧 전투 준비**가 되어 두 기둥이 물린다.

### 4-3. 미구현

효과 4종은 **문서만.** 코드 연결 필요. 정화도 자체는 `purifiedAreas` / `purifyFoci`로 이미 셀 수 있다.

## 5. 구조(LIFE 정화) 밸런스 재조정 【확정 2026-08-08】

### 5-1. 이전 문제

`buildRescueOptions`의 턴별 선택지 페어:

| 확률 | 페어 | GOOD 가능? |
|---:|---|---|
| 50% | 좋아함 vs 싫어함 | ✅ |
| 30% | 좋아함 vs 무난 | ✅ |
| **20%** | **싫어함 vs 무난** | **❌ 최선이 NEUTRAL** |

이전 수치(GOOD +28 / NEUTRAL +10 / goal 100 / 5턴)에서는:

- 완벽하게 골라도 **5턴을 거의 다 써야** 100에 닿는다
- GOOD 불가 턴이 3회 뜨면(약 **6%**) **실력과 무관하게 실패**
- 20마리 전부 `goal=100 / max_turns=5` — **커브 없음**

`39` §4에서 「실패 = 아이 상실」이 확정된 뒤로, 6% 순수 운 실패는 가혹함이 아니라 **부당함**이다.

### 5-2. 조정 후

`combat_tuning.csv`:

| 키 | 이전 | 현행 |
|---|---:|---:|
| `rescue_good_purify` | 28 | **30** |
| `rescue_neutral_purify` | 10 | **15** ← GOOD 불가 턴의 부당한 실패를 막는 하한 |
| `rescue_bad_purify` | -8 | **-10** |
| `rescue_purify_variance` | 3 | 3 |

`rescue_animal_config.csv` — `purify_goal` 커브 (`max_turns`는 5 유지):

| 구역 | goal | 필요 적중 | 실수 여유 |
|---|---:|---:|---:|
| map_1 부두 | **75** | **3회** | 2턴 |
| map_2 | **90** | **3회** | 2턴 |
| map_3 | **100** | 4회 | 1~2턴 |
| map_4 | **110** | 4회 | 1턴 |

### 5-3. 검산

- 부두: 3×30 = 90 ≥ 75 ✓ (최악값 3×27 = 81도 통과) → **적중 3회로 성공**
- GOOD 불가 턴 3회(약 5%)여도 부두는 GOOD 2 + NEUTRAL 3 = 60+45 = 105 ≥ 75 ✓ → **운으로 실패하지 않는다**
- map_4: 4×30 = 120 ≥ 110 ✓ / GOOD 3 + NEUTRAL 2 = 90+30 = 120 ✓ → 후반은 팽팽하지만 길이 있다

> 힌트문(`hint_text`)이 좋아하는 접근을 그대로 알려준다. **읽으면 맞는** 구조 — 코지 톤에 맞는 의도된 설계이며, 지능 퍼즐이 아니다.

## 6. 구현 현황 (2026-08-08 실측)

### 6-1. 구현 완료 ✅

| 항목 | 코드 | 검증 |
|---|---|---|
| **섹터 이동 = 하루** | `explore.ts` `travel()` → `onSectorTravel` 훅 → `main.ts` `advanceDay()` | i11→i12 이동 시 Day 1→2 ✓ |
| **배가 오는 날(60일)** | `advanceDay()` → `showVoyageEndScreen()` | 59일 + 이동 1회 → 귀환 화면 ✓ |
| **실패 = 아이 전부 상실** | 전투 패배 분기 → `showRunFailScreen()` | 아이·로스터·도감 전부 비워짐 ✓ |
| **부두 관문 하드** | `area_connection_config` `NODE:s1_gate` | 부두 십자 패드 🔒「관문 필요」 ✓ |
| **중앙 i11 노드 4개** | `area_npc_config` +4행 | 전망대·쉼터·촉매·오염 표시 ✓ |
| **전망대 = 섬 정화도 읽기** | `runMapNode` `case "MEMO"` | 「정화도 0% (0/5) · 다음 25% · 배까지 59일」 ✓ |
| **정화도 75% 효과** | `playRescueEncounter` 시작 정화도 +15% | 코드 반영 |
| **구조 밸런스 커브** | `combat_tuning` + `rescue_animal_config` | §5 |
| 파견 → 정찰 문구 | `settleIslandDispatch()` — 「🐾 정찰 보고」 | `39` §5-1 |

> **주의(교훈):** MEMO 노드는 `explore.ts` `approach()`가 자체 처리해 `runNode`를 호출하지 않았다.
> 전망대를 붙이려면 MEMO도 main으로 넘겨야 했다 — 지금은 MEMORY만 explore가 직접 처리한다.

### 6-2. 검증 훅 (콘솔)
