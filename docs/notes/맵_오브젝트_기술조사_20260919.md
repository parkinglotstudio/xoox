## A. 맵 / 지형 파이프라인

### A-1. 공간 모델 (확정)

한 섬 ≈ **1 km**, **3×3 = 9칸**, 칸 ≈ **333 m**. 보행은 육지 십자 5칸만.

```
i00 미니맵   i01 북부 큰숲   i02 미니맵
i10 서부     i11 중앙         i12 동부
i20 미니맵   i21 들판·스폰    i22 미니맵
```

- 코너 4칸(`i00/i02/i20/i22`)은 **바다 구멍이 아님**. 미니맵용 육지(숲/산). 보행만 불가.
- 스폰 = `area_i21` (`is_spawn=TRUE`). 현재 컨셉은 **부두가 아니라 남쪽 들판**.
- 문서 상수: `data/ui/layout/journey_tiles.json` (`walkable`, `sea_corners_art_only`). **`src/`는 이 JSON을 읽지 않음** — 코드 쪽은 `LAND_SECTOR_IDS`에 같은 집합을 하드코딩.

### A-2. 저작 형식 (무엇이 “원본”인가)

| 형식 | 역할 | 본편 런타임이 읽는가 |
|---|---|---|
| 마스크 JSON (`MaskDoc`) | 섬 면·작업구역·숲/들/물/바위 등 **레이아웃 SSoT** | **아니오** (툴·배치 스크립트만) |
| 섹터 컨셉 PNG 2048² | 미니맵·에디터·3D 바닥 스플랫 입력 | **예** (`sector_scale.json` URL) |
| `sector_scale.json` | 미터·안개·섹터별 after/before 경로 | **예** |
| `journey3d_layout.json` | 3D 렌더 스케일·카메라·안개 | **예** |
| CSV (`area_*`) | 구역 그래프·노드·존·프롭 | **예** (`src/data.ts`) |
| floor 타일 PNG | 스플랫이 찍는 지면 텍스처 | **예** (스플랫 경로) |
| `tileset/` 디테일 스탬프 | README에 **예정** | 디렉터리 없음 |

마스크 스키마 (`src/mapMaskTool/types.ts`):

```text
MaskDoc = { version, sector_id, size, note, layers: Partial<Record<LayerId, dataURL PNG>> }
LAYER_IDS = land, walk, path, forest, flower, pond, lake, rock,
            debris, blight, farm, village, dock, node, poi
```

- `walk` = “갈 수 있는 땅 전부”가 아님. **인게임 타일 작업 구역**(십자). `walk` 밖 ∩ `land` 안 = 미니맵만.
- Phase 0→4: 레이아웃 → 외곽(림) → 작업구역 → 소프트 액센트 → 미리보기. `MASK_PHASES`.
- `farm` / `village` / `dock`는 레이어 정의에 있으나 **enabled: false** (거주 아트 보류).

**핵심 갭:** 마스크는 툴·파이프라인 SSoT이지만, **본편 3D 바닥은 마스크 레이어를 직접 스탬프하지 않는다.** 컨셉 PNG를 분석해 타일을 섞는다.

### A-6. 런타임 로드 경로

```
src/main.ts init()
  → loadGameData()          // src/data.ts — 위 CSV
  → initExplore()           // 탑뷰 미니맵 (로비에서도 가능)
  → enterJourney()
      → initJourney3D()     // 외출 때 WebGL. 로비에서는 IslandTerrain 없음
          Journey3DView.enter(areaId)
            → loadJourney3DConfig()
            → IslandTerrain (스폰 칸 우선, 이웃 BFS)
            → scatterForArea()  // area_prop_config만
            → refreshNodes()    // area_npc_config
```

| 층 | 모듈 | 로드하는 것 |
|---|---|---|
| 탑뷰 | `src/explore.ts` `ExploreView` | `area_config` 배경, 연결, NPC. `sector_scale.json`으로 액터·안개 |
| 3D 글루 | `src/stage/world3d/Journey3DView.ts` | 바닥 + CSV 프롭 + 노드 + 정화 루프 |
| 3D 무대 | `JourneyStage3D.ts` | 카메라, 빌보드, 해안 InstancedMesh, 원경 원통 |
| 바닥 | `IslandTerrain.ts` | 물 플레인 + 육지 5칸 메시 |
| 스플랫 | `islandFloorSplat.ts` | 컨셉 PNG → 타일 캔버스 (`SRC=768`, `OUT=2048`) |
| 스트리밍 | `islandLoadOrder.ts` | `LAND_SECTOR_IDS`, `landLoadOrder()` i21→i11→나머지 |
| 좌표 SSoT | `islandMapShared.ts` | 스케일 URL, 컨셉 URL, 마스크 URL (마스크 URL은 툴용) |

`IslandTerrain.paintLand()` 요약:

1. `conceptUrlFor(..., purified=true)` → **`sector_*_after.png`만**.
2. `paintSectorFloorFromImage()` / `analyzeConceptMesh()` — 바다 flood-fill, 지붕/오브젝트 인페인트, 타일 스탬프.
3. 알파 = 바다 마스크. 오염 = 셰이더 틴트 (`POLLUTED_TINT`), before PNG 스왑 아님.
4. `stickerDrafts`를 컨셉 blob에서 뽑지만 **본편 `scatterForArea`는 쓰지 않음**.

레거시: `JourneyStage3D`의 옛 `floor`/`detail` 메시는 `island.ready` 후 `visible=false`. 주석: 타일 섬이 올라오면 디테일 오버레이를 끈다.

좌표 동기: 3D가 이동을 소유 → `onMove` → `explore.syncFrom3D(xPct, yPct, yawDeg)`. 칸 이동: `explore.onAreaChange` → `journey3d.enter`.

## B. 오브젝트 / 프롭 표현

### B-1. 런타임 표현 (있는 것 / 없는 것)

| 기법 | 사용처 | 비고 |
|---|---|---|
| **세로 빌보드 `THREE.Mesh` + 공유 `PlaneGeometry(1,1)`** | 일반 프롭 | 둠식 세움판. 기본 `billboard=true` (카메라 yaw) |
| **PNG 스티커** | `data/art/props/sticker/` | `WorldProp.art` → `/art/props/sticker/{file}` |
| **절차 캔버스 폴백** | `propArt.ts` | `art` 없으면 `PropKind`별 `CanvasTexture` |
| **텍스처/머티리얼 공유** | `stickerArtTexture` / `stickerArtMaterial` | 같은 PNG = 1장. 최대 512px, 알파 펀치 |
| **`THREE.InstancedMesh`** | `group_id === "sea_wall"`만 | 아트 URL별로 배치. 거리 스트리밍 |
| **`THREE.Sprite`** | `WorldNode` (NPC 마커) | 프롭 CSV와 분리 |
| **바닥 스플랫 메시** | `IslandTerrain` | 타일 캔버스. 프롭 아님 |
| **컨셉 blob → 스티커 초안** | `backgroundProps()` | 구현됨, **본편 enter에 미연결** |
| **시드 난수 스캐터** | `scatter.ts` `scatterProps()` | CSV가 있으면 우선. **importer 없음** |
| GLTF / `.glb` / 병합 지오메트리 / 텍스처 아틀라스 / 프롭 LOD | — | **없음** |

타입 (`src/stage/world3d/types.ts`):

```text
PropKind = building | tower | fence | sign | crate | barrel | pole | tree | bush | debris
WorldProp = id, xPct, yPct, kind, hM?, aspect?, art?, billboard?, yawDeg?,
            tint?, collide?, collideR?, purifyTarget?, lifeBlightId?, groupId?
```

`PROP_DEFAULTS` (`propArt.ts`): 전 kind `billboard: true`. 예: tree 6.4 m, building 12.5 m, bush 1.35 m.

스티커 로스터 (`data/art/props/sticker/roster.json`):

- `nature_active`: tree_04~07, grass_01~03, flower_01~03 — 노트는 “CSV에 연결됨”
- `nature_draft`: tree_01~03 — “파일 보관, CSV 미사용”
- houses 4종, 일반 props (tower/fence/sign/crate/barrel/pole/lantern/debris/life_mecha_dog)

**실제 커밋된 `area_prop_config.csv`:** 361행, **전부 `sea_wall`**, art는 `prop_sticker_tree_06.png` / `tree_07.png`. 구역: `area_i21` 82, `i10`/`i01`/`i12` 각 93. **`area_i11` 0행.** 들판 나무(tree_04/05)·풀·꽃·집은 라이브 CSV에 없음.

스티커 PNG는 체크아웃에 **존재함** (`prop_sticker_tree_01`~`07`, grass, flower, houses, …).

### B-2. 배치 데이터 포맷

**SSoT 헤더** (`data/area_prop_config.csv` = `AreaPropDef` in `src/types.ts`):

```text
prop_id, area_id, kind, x_pct, y_pct, yaw_deg, h_m,
group_id, collide, purify_target, life_blight_id, art, note
```

| 필드 | 의미 |
|---|---|
| `x_pct`, `y_pct` | 섹터 맵 0–100. y=0 북(아트 위) = 3D −Z |
| `yaw_deg` | 고정 평면일 때. 빌보드는 카메라가 덮음 |
| `h_m` | 높이(m). 폭 = `hM * aspect` (`stickerTrees.aspectForPropArt`) |
| `group_id` | 특수: **`sea_wall`** = 해안 방벽 인스턴싱 + 개별 메시 스트림에서 제외 |
| `collide` | 원반 장애물. 기본 반경 `COLLIDE_R` (tree 1.35, building 2.6, …) |
| `collideR` | CSV에 컬럼 없음. `propFromCsv`가 sea_wall에 tree_07=2.6 / 그 외=2.05를 넣음 |
| `purify_target` | AREA 파도 후에도 스케치 → 칼라 총 |
| `life_blight_id` | 생명 뭉치 blight FK. **월드 코드가 읽지 않음** |

코드가 이미 적은 성능 메모:

- `rebuildWallBatch`: 「장마다 메시를 만들면 이 밀도에서 버벅인다.」

### C-2. 좌표계 · 카메라

**% 좌표 (2D ↔ 3D 공유)**  
`x_pct`/`y_pct` 0–100. y=0 북 = 3D −Z. yaw 0° = 북(−Z).

**미터 — 두 스케일**

| 이름 | 값 | 의미 |
|---|---|---|
| `sector_world_*_m` / `SECTOR_M` | **333** | 설계 “실제” 칸. 멀티섹터 절대 원점 |
| `island_world_m` | 1000 | 섬 한 변 |
| `world_m` (레이아웃 JSON) | **110** (코드 기본 70) | **한 칸을 몇 m로 그릴지.** %는 그대로라 미니맵은 안 깨짐 |
| `character_height_m` (스케일 JSON) | 1 | 2D 에디터 비유 |
| `char_height_m` (3D JSON) | **1.95** | 3D 방랑자·원경 배수. GDD 46: 두 숫자를 섞지 말 것 |
| `centerOnFocus` | true | 활성 칸을 원점으로 당겨 그림 |

`areaToWorld` / `sectorOrigin`: 그리드 칸 원점. 포커스 모드에서는 로컬 xz ≈ 플레이어 월드.

**카메라** (`journey3dConfig.ts`, GDD 46):

- `PerspectiveCamera`, FOV **72**, 기본 **`view_mode: "tps"`** (등 뒤, 플레이어 스프라이트 보임).
- TPS: `tps_distance_mul=3.2` · `tps_height_mul=1.9` → 거리 ≈ 6.2 m, 높이 ≈ 3.7 m. lookAt ≈ 수평.
- `"fps"`: 플레이어 스프라이트 숨김. `fpv-tool` / `setViewMode`.
- 원경: 원통 한 장, 반지름 ≈ fog.far×0.86, 높이 `charH*18`, xz는 카메라를 따라감.

탐방 안개(탑뷰) `fog_vision_m=10` (GDD 45)와 3D fog `30`은 **다른 노브**.

배치 함의: 카메라는 거의 수평이라 **근경 빌보드(나무·풀)가 “옆 풍경”**이고, 먼 산은 원통. 탑뷰 섹터 PNG에 산을 구워 넣지 않는다. 밀도·높이는 TPS 발밑(world_m 110 ≈ 3.4 m/섹터%)에 맞춰야 한다. 333 m 설계 밀도를 그대로 심으면 발밑에 과밀·원경에 공허해진다.

### D-3. 설계 의도 (배치 논의용으로 압축)

1. **공간 = RPG.** 콘텐츠는 날짜가 아니라 칸·노드에 붙는다. 왕복이 가능해야 한다.
2. **한 통짜 섬.** 칸마다 다른 섬 모양 금지. 코너는 바다로 비우지 않음.
3. **바닥과 소품은 나중 레이어.** 마스크로 구역을 읽히게 한 뒤, 타일+빌보드로 채운다. 복셀/박스 높이는 후순위(해안만 타협 후보).
4. **거주는 선반.** 집·부두·마을 아트는 마스크에서 꺼 두었고, 해당 프롭은 `i21_props_shelved.csv`.
5. **근경은 스티커, 원경은 원통.** 섹터 PNG에 산을 넣지 않음.
6. **들판 손맛**은 다섯 자리 + 해안 나무/들풀 그래픽. 라이브 월드는 아직 해안 `sea_wall` 나무 띠가 그 의도에 가장 가깝다.
7. **반복 소품은 싸게.** 해안 밀도에서 이미 InstancedMesh+스트림을 넣었다. 내륙 RPG 밀도는 같은 패턴의 일반화가 자연스러운 다음 기술 질문이다.

### E-3. 더  dense한 RPG 배치를 막는 것

1. **라이브 SSoT가 해안 띠뿐.** 심으면 바로 보이는 파이프는 있다. 들판/숲을 채운 승인권 CSV가 없다.
2. **인스턴싱이 `sea_wall` 특수 케이스.** 같은 나무 200그루를 `group_id` 없이 심으면 개별 Mesh+스트림(34 m). 풀/꽃까지 가면 draw call이 먼저  explodes.
3. **렌더 미터 ≠ 설계 미터.** 333 m 설계 간격으로 심고 110 m로 그리면 발밑이 과밀. 배치 툴/CSV에 “어느 스케일 기준인가”가 없음.
4. **충돌이 전부 원반.** 울타리 줄·바위 군집·좁은 숲길은 원을 겹치면 길이 막히거나 통과한다. `path` 마스크는 보행 메시가 아님.
5. **마스크와 3D가 한 소스가 아님.** 숲 마스크를 바꿔도 나무는 안 움직임. 더블 소스(페인트 vs CSV).
6. **카메라가 수평 TPS.** 낮은 풀은 발밑에만 보이고, 키 큰 해안 나무는 실루엣이 됨. 종류·높이 믹스가 필요.
7. **상호작용 슬롯이 얇음.** 줍기=노드, 잔여칠=`purify_target`, 생명뭉치=미배선. “조사할 바위/상자”를 프롭으로 늘리면 훅을 더 열어야 함.
8. **i11 허브가 비어 있음.** 중앙을 지날 때 해안 띠도 없음.

### E-4. 다음에 고를 수 있는 기술 옵션 (하지 말 것, 선택지만)

논의용. 이 조사는 구현하지 않음.

**A. CSV를 채우기만 (최소)**  
`prop-place-tool`을 tree_04/05(+풀/꽃)에 맞추고, 해안 `sea_wall` keep, 들판/숲에 수십~백 단위로 심기. 엔진은 그대로. 리스크: 비-wall 스트림 비용, 스케일 혼선.

**B. `group_id` 인스턴싱 일반화**  
`sea_wall` 패턴을 `art` 또는 `group_id`(forest, meadow_grass, …)로. 같은 스티커 반복을 InstancedMesh+스트림. 사용자 요청(반복 자원 싸게)과 가장 맞음. GLTF 불필요.

**C. 마스크 → 스캐터 (타일 파이프 Phase D)**  
`forest`/`flower`/`rock` 알파에서 런타임 또는 베이크 시 CSV/바이너리 포인트 클라우드. 레이아웃과 소품이 한 그림. 베이크면 결정론·검수 가능. 런타임이면 시드·퍼포먼스 정책 필요.

**D. 바닥은 마스크 스플랫, 소품은 빌보드**  
컨셉 PNG 추정 대신 마스크 레이어로 타일 가중치. 바닥↔에디터 정렬. 프롭과 독립적으로 가능.

**E. 해안만 낮은 메시 (문서의 보류)**  
`rock` 링만 박스/로우폴리. 나무는 빌보드 유지. 비용 대비 이득은 해안 실루엣이 빌보드로 부족한지 본 뒤.

**F. 하지 않는 편이 좋은 것 (문서가 이미 금지)**  
풀 복셀 섬, 칸마다 다른 실루엣, 승인 전 아트 대량 투입, 섹터 PNG에 산 베이크, 하늘/산을 따로 명작, region-kit을 섬 바닥에 붙이기, GLTF 파이프를 밀도 문제의 첫 답으로 쓰기.
